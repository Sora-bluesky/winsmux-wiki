# ローカルモデル {#local-models}

Hermes はオープンなモデルを、自分の端末のなかだけで動かせます。推論エンジン
（llama.cpp）のダウンロードと管理、手元のハードウェアに合うビルドの選択、
メモリのやりくりまで Hermes が引き受けるので、コンテキスト長も GPU
レイヤー数も量子化も設定せずに済みます。使う人はモデルを選ぶだけで、
あとは Hermes がやります。

何も端末の外には出ません。アカウントも API キーも要らず、モデルを
ダウンロードしたあとはネットワークにもつなぎません。

## 導入 {#getting-started}

1. **設定 → Providers → Local Models** を開きます（初回設定の途中で
   **Run models locally** を選んでも構いません）。
2. **Install runtime** を押します。手元のハードウェア向けの公式 llama.cpp
   ビルド（数百 MB）を Hermes がダウンロードして検証し、以後は最新に
   保ちます。
3. カタログからモデルを選んで **Download** を押します。
4. **Use** を押します。これ以降の新しいチャットは、ローカルのモデルで
   動きます。

流れはこれで全部です。サーバーは Hermes と一緒に起動・終了し、アプリを
再起動しても設定は残ります。クラウドのプロバイダーに戻したいときも、
モデル選択欄で 1 回押すだけです。

## Hermes が何をダウンロードするか決めるしくみ {#how-hermes-picks-what-to-download}

カタログに並ぶモデルは、ダウンロードする前に **手元の端末** を基準に
値踏みされます。各行に出るのは次の情報です。

- **メモリの収まり** — 緑（*Fits your GPU*: GPU メモリだけで動きます）、
  黄（*Uses system RAM*: 動きますが遅くなります）、赤（*Too big for this
  machine*: この端末には大きすぎます）。
- **コンテキスト** — そのモデルが最初に使う長さと、伸ばせる上限。
- 手元のハードウェア向けに選ばれたビルドのダウンロードサイズ。

モデルにはいくつかの品質段階（量子化）があります。Hermes は GPU だけで
動き切るなかで最も品質の高いビルドを選び、メモリの少ない端末には同じ
モデルのより小さなビルドを同じ保証のまま渡します。4 ビットを下回ると
品質の落ち方が大きすぎるので、それより小さいビルドは用意しません。
システム RAM にあふれさせた 4 ビットのビルドすら動かせない端末では、
そのモデルは動かない、ということです。

収まらないモデルも理由付きで表示に残るので、ハードウェアを増強すると
何が使えるようになるかがいつでも分かります。

## メモリ管理のしくみ {#how-memory-management-works}

ローカルのモデルはメモリの置き場所で生き死にが決まります。そのため
Hermes が最初から最後まで管理し、つまみは一切出しません。

- **モデルは GPU に完全に収まるコンテキスト長で始まり**、会話が長くなって
  余地が要るにつれて本来の上限へ向けて伸びていきます。長い作業の途中で
  ステータス欄に "Context window grown" と出ることがありますが、これは
  長さが伸びただけでエラーではありません。
- **推奨モデルには最低でも 64K のコンテキスト長が確保されます。** モデルが
  GPU のメモリより大きいとき、Hermes は影響のいちばん小さい順（まず
  エキスパートの重み、アテンションのキャッシュは決して動かしません）で
  あふれた分をシステム RAM に置き、速度をいくらか譲ってこの長さの保証を
  守ります。
- **メモリの収まりは起動時の構成込みで数えます。** モデルのファイルだけ
  ではなく、コンテキストの状態、ランタイムのバッファ、画像認識用の
  プロジェクタ、MTP のバッファまで勘定に入ります。マルチトークン予測
  （MTP）では、大きなバッチだと同じコンテキスト長であふれてしまう場合に
  小さなバッチを使います。MTP 自体は有効なままです。再起動後に伸びた
  長さを復元するときも、同じ計算が走ります。
- **会話の圧縮は、長さを伸ばせるかを確かめたうえで行われます。** もっと
  長い窓が収まらない、生成が遅すぎる、あるいは本来の上限に届いた場合、
  Hermes はサーバーが受け取っていない長さを名乗る代わりに、会話を圧縮
  します。
- 使われていないモデルは 15 分で読み込みを解いて GPU メモリを空けます。
  次のメッセージが来れば自動で読み直します。

## ステータスバー {#the-status-bar}

ステータスバーを右クリックして **System resources** を有効にすると、
ローカルのモデルが動いている間の GPU 使用率・GPU メモリ・RAM を
その場で確認できます。コンテキストのメーターは、モデルが実際に使って
いる長さを常に映します。

## もっとモデルを探す {#finding-more-models}

カタログは選りすぐりの出発点であって、そこで打ち止めではありません。
同じページの **Find more models** から Hugging Face 全体を検索できます。

- 検索結果にはダウンロード数と、手元の端末に合わせたファイル単位の
  収まり判定が出るので、GPU だけで動き切るかどうかをダウンロード前に
  確かめられます。
- 落としてきたモデルはカタログのものとまったく同じように動きます。
  Hermes がモデルのファイル自体を読んで、コンテキスト長とメモリの
  置き場所を決めるからです。違うのは、コミュニティのモデルには
  こちらの「検証済み」バッジが付かないという点だけです。
- すでに `.gguf` のファイルを持っているなら、**Add model file** で
  コピーせずに手持ちに取り込めます（元のファイルはその場に残ります）。
  取り込んだらすぐ使えます。

## 自前の llama-server を使う {#using-your-own-llama-server}

すでに llama-server が端末で動いている場合、Hermes はそれを見つけて、
自前のサーバーを起動せずにそちらを使います。OpenAI 互換のサーバーで
あれば、カスタムのエンドポイントを向けて全部を手動で握ることもできます。
付属のランタイムはあくまで既定であって、必須ではありません。手動で
組む場合（Ollama、MLX、独自ビルド、画面のない CLI の端末など）は
[Run Hermes Locally with Ollama](/hermes/docs/guides/local-ollama-setup/) と
[Run Local LLMs on Mac](/hermes/docs/guides/local-llm-on-mac/) を見てください。

## 設定 {#configuration}

付属のランタイムは `config.yaml` の `local_runtime` セクションで制御します。
デスクトップの画面がこの値を書いてくれますが、CLI や画面なしの運用の
ためにここに載せておきます。

```yaml
local_runtime:
  enabled: false     # true = start the managed server with Hermes.
                     # The desktop "Use" button sets this automatically.
  backend: auto      # auto | cuda | metal | vulkan | hip | cpu
  tag: b10362        # pinned llama.cpp release; Hermes updates it with
                     # each release after re-validation
```

モデルとランタイムのビルドは Hermes のホームディレクトリの下
（`models/` と `runtimes/llamacpp/`）に置かれます。ローカルのモデルを
主役のモデルに据えるときは、いつもの `model.provider: llamacpp` と
`model.default` の設定を使います。ほかのプロバイダーとまったく同じ形です。

## 必要なものと限界 {#requirements-and-limits}

- **Windows と Linux:** NVIDIA の GPU（CUDA）または CPU。**macOS:** Apple
  Silicon（Metal）。AMD の GPU には Vulkan のビルドが使われます。
- メモリ 8 GB 以上の GPU があればカタログの小さめのモデルは快適に動き、
  16 GB 以上なら 27〜35B のモデルを高い品質で動かせます。
- モデルのダウンロードは転送中にカタログのバイト数と突き合わせます。
  途中で欠けたものは削除して報告するので、中途半端なまま使われることは
  ありません（SHA-256 で検証するのはランタイムのエンジンの zip だけです）。
- モデルを削除すると、画像認識のアダプタや投機的デコード用の相棒まで
  含めて、そのモデルが置いたファイルをすべて消します。
