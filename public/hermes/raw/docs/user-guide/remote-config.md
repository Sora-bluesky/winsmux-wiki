# リモート設定 {#remote-config}

**リモート設定モード**では、`config.yaml` の代わりにコンフィグプレーン（設定の配信基盤）を使います。
各プロファイルの設定は、このエージェントインスタンスとそのプロファイルに対して
プレーンが組み立てたドキュメントになります。プレーンはグローバル、テナント、グループ、オーナー、
エージェントの設定を順に重ね、最後にプロファイル自身の設定を適用します。管理者は上位のレベルで
キーをロックでき、ロックされたキーはエージェント側から変更できません。

リモート設定は、Hermes Cloud のように多数のエージェントをまとめて運用する環境（フリート展開）向けです。
ユーザーが1人だけの単一の端末では、引き続き `config.yaml` を使ってください。

## 有効にする {#turning-it-on}

環境変数、`~/.hermes/.env`、または管理用の
`/etc/hermes/.env`（ほかの2つより優先されます）に、次の値を設定します。バックエンドは設定を配信する側そのものなので、
`config.yaml` に書いた値でバックエンドを選ぶことはできません。

| 変数 | 意味 |
|---|---|
| `HERMES_CONFIG_BACKEND=remote` | `config.yaml` の代わりにコンフィグプレーンを使います（既定値は `file`）。 |
| `HERMES_CONFIG_INSTANCE_ID` | プレーン上でのこのエージェントの ID です。Hermes Cloud では自動で設定されます。オンプレミスでは、エージェントを登録するときに運用担当者が設定します。必須です。 |
| `HERMES_CONFIG_REMOTE_URL` | プレーンのベース URL です（既定値は `https://config-config.nousresearch.com`）。 |

エージェントは、エージェント自身の資格情報で認証します。

- **Hermes Cloud**: プロファイルの `auth.json` にある Nous のアクセストークンを使います。
- **オンプレミス**: お使いの ID プロバイダーが発行する OAuth2 クライアントクレデンシャルトークンを使います。
  `.env` で `GATEWAY_RELAY_IDP_TOKEN_URL`、
  `GATEWAY_RELAY_IDP_CLIENT_ID`、`GATEWAY_RELAY_IDP_CLIENT_SECRET`、
  必要に応じて `GATEWAY_RELAY_IDP_SCOPE` を設定します。

これらの値と、上記の `HERMES_CONFIG_*` 変数は、
`auth.json`、`.env` ファイル（プロファイルのもの、Hermes コマンドが読み込むプロジェクトの `.env`、
または管理用のもの）、あるいはプロセスの環境変数から渡す必要があります。`secrets:` のソース
（1Password、Bitwarden、コマンド）がこれらのいずれかを提供している場合、Hermes は起動を拒否します。
`HERMES_PORTAL_BASE_URL`、`NOUS_PORTAL_BASE_URL`、
`HERMES_SHARED_AUTH_DIR` も同様です（これらは Cloud トークンをどこから読み、どこへ送るかを決めるためです）。
複数のプロファイルを扱うプロセス（gateway、dashboard）は、
`secrets:` のソースがこれらの名前のいずれかを提供しているプロファイルについては、そのプロファイルの提供を拒否します。

別のプロファイル用に起動された Hermes プロセス（`hermes -p <name>` のワーカーや、
プロファイルの cron・ボットの子プロセス）は、起動元プロセスの `HERMES_CONFIG_*` のデプロイ設定を
引き継ぐため、そのプロファイルの設定もプレーンから読み込みます。
ただし、プレーンへの認証情報は引き継ぎません。オンプレミスでは、
`GATEWAY_RELAY_IDP_*` の値をすべてのプロファイルが読み込む場所（管理用の
`/etc/hermes/.env`）か、各プロファイルの `.env` に置いてください。認証情報がない場合、
プロセスはローカルファイルを読むのではなく、エラーで終了します。

## 変わること {#what-changes}

- **起動時に設定を取得し、取得できなければ安全側に倒して停止します。** すべての Hermes プロセス（gateway、
  dashboard、CLI、ターミナルの子プロセス）は、`.env` を読み込む時点でプロファイルの設定を取得します。
  約30秒間再試行してもプレーンに接続できない場合や、プレーンがエージェントを拒否した場合、
  プロセスはエラーで終了します。ローカルファイルや既定値に切り替えて動き続けることはありません。
- **ローカルの設定ファイルはありません。** `config.yaml` は読み込みも書き込みもされず、
  ローカルキャッシュもありません。実行中のプロセスは、最後に取得した設定をメモリ上に保持します。
  Hermes の実行中にプレーンに接続できなくなった場合も、プロセスはメモリ上の設定で動き続け、
  次のポーリングで再試行します。
- **変更はポーリングで届きます。** 各プロセスは5分ごとに変更を確認します。
  プレーンで行った変更は、1回の間隔のうちに実行中のエージェントへ反映されます。
- **書き込みはプロファイル自身のレベルに対して行われます。** `hermes config set`、`/model`、
  dashboard など、設定を書き込むあらゆる手段は、変更されたキーだけを送信し、
  同時編集から保護されます。その間に別のプロセスがプロファイルを変更していた場合、
  Hermes はプロファイルを読み直し、自分の変更だけをその上に適用します。相手の変更を取り消すことはありません。
  キーを削除しても、削除されるのはプロファイルレベルの値だけです。
  上位のレベルでも同じキーが設定されていればその値が引き続き適用され、Hermes が
  警告を表示します。
- **ロックされたキーへの変更は拒否されます。** ロックされたキーに対して `hermes config set` を実行すると
  （TUI やデスクトップアプリでの設定変更も同様で、プロンプト、推論の表示、
  詳細モードの設定も含みます）、どのレベルでロックされているかが表示され、何も変更されません。
  ドキュメント全体を保存する場合は、ロックされたキーは除外され、
  Hermes がそれらを一覧にした注意書きを表示します。
- **シークレットはプレーンに置きません。** `api_key` のようなシークレットにあたるキーには
  `${VAR}` 形式の参照しか指定できず、シークレットそのものは受け付けません。値は
  `.env` かシークレットソースに置き、参照を設定してください。

  ```bash
  hermes config set model.api_key '${OPENROUTER_API_KEY}'
  ```

- **`secrets:` もほかのキーと同じくプレーンから取得されます。** そのため管理者は、
  シークレットソースの設定を一元的に管理し、ロックできます。
- **スキーマの移行はメモリ上で行われます。** 古い Hermes が書き込んだドキュメントは
  読み込み時に移行され、その結果は書き戻されません。その後に新しい Hermes が書き込む場合も、
  データがすでに最新でない限り、プロファイルに保存されているスキーマバージョンは維持されるため、
  後から読み込むすべてのプロセスが引き続き移行を行います。これらの
  メモリ上の移行で変わるのは設定ドキュメントだけです。ローカルファイルも
  整理する手順（`SOUL.md` から廃止されたセクションを削除する、`.env` から古い値を
  消すなど）は、リモートモードでは実行されません。
  同じ理由で、こうした移行のいずれかが書き換える値（たとえば、古いスキーマで保存された
  プロファイルに対して、以前の既定値である `compression.threshold_tokens: 256000` を設定する場合）は、
  キー名を示すメッセージとともに拒否されます。保存されても、
  二度と読み戻されないためです。
- 取得したドキュメント内の**未知のキー**は、警告を表示したうえで無視されます。
  たとえば、新しい Hermes で追加されたキーなどです。

## 管理スコープ {#managed-scope}

`/etc/hermes/config.yaml`（[管理スコープ](/hermes/docs/user-guide/managed-scope/)を参照）は、
リモートモードでは**無視されます**。設定とロックはプレーンからのみ取得されます。Hermes は
起動時に警告を表示し、`hermes doctor` もこのファイルを指摘します。管理用の
`/etc/hermes/.env` は引き続き適用されます。

## 設定ファイルを操作するコマンド {#commands-that-work-on-the-config-file}

次のコマンドは `config.yaml` をコピーまたは編集するため、リモートモードでは実行を拒否されます。

- `hermes config edit`（代わりに `hermes config set` を使ってください）
- プロファイルの複製、プロファイル名の変更（プレーンはプロファイルの設定を
  その名前で管理しているため）、プロファイル配布パッケージのインストール
- `hermes backup`、`hermes import`、スナップショットの復元
- `hermes gateway --config <file>`

`hermes doctor` は、ファイルの代わりにバックエンドの情報を表示します。表示されるのは、プレーンの URL、
プロファイル、プロファイルレベルのバージョン、ロックの数、設定を
最後に取得した時刻です。
