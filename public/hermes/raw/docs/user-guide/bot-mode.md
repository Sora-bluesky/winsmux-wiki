# Bot モード {#bot-mode}

**Bot モード**は、[Hermes のプロファイル](/hermes/docs/user-guide/profiles/)を、名前を持った **Bot** の一覧に変えます。それぞれの Bot は自分の役割・モデル・記憶・スキル・アバターを持ち、繰り返しの定期タスクを実行し、グループチャットで一緒に検討し、Bot 同士で直接メッセージを送り合います。専門役の Bot を一度作れば、その後はずっとそこにいて、クリック一回で呼び出せます。

Bot モードは**[デスクトップアプリ](/hermes/docs/user-guide/desktop/)に組み込み済み**で、**既定で有効**です。追加のインストールは要りません。左サイドバーの Sessions の隣に **Bots** タブとして現れ、Bots タブを開いている間は会話の横に **Routines** のタイルが並びます。

:::tip Bot はプロファイルそのもの
新しく覚える仕組みはありません。Bot は Hermes のプロファイル**そのもの**で、設定・記憶・スキル・認証情報・チャット履歴が `~/.hermes/profiles/<name>/` の下で切り離して保存されます。Bot モードはその仕組みに UI をかぶせたものなので、そこでやったことは CLI からもそのまま見えます。`hermes -p <bot> chat` を実行すれば同じエージェントが開き、Bot の定期タスクは `hermes cron list` に出てきます。本体へのパッチも、常駐プロセスも、余分な保存領域も要りません。
:::

## Bots ペイン {#the-bots-pane}

一覧には、エージェントのプロファイル 1 つにつき 1 行が並びます。アバター、直近メッセージのプレビュー、時刻が表示されます。

- **Bot をクリック**するとそのチャットに入ります。どの Bot にも、生まれた瞬間に作られて（そして固定される）正式な **Bot Chat** という会話が 1 本ずつあり、ずっと残ります。
- **Active now** — 一覧の上の在席バーに、いま働いている Bot がすべて出ます。ゲートウェイが処理中のプロファイルと、直近 90 秒以内に発言した Bot が対象です。それぞれのチップをクリックするとその Bot のチャットが開きます。このバーが一覧の並び順を変えることはなく、全員が手空きになると消えます。
- **検索**すると、入力にあわせて一覧が絞り込まれます。
- **Bot を隠す** — 行を右クリックして **Hide Bot** を選ぶと、使っていない Bot を一覧と Active now バーから外せます。隠すのは表示上だけの操作です。@メンションは今までどおり届き、グループチャットの所属も変わらず、定期タスクも動き続けます。1 つでも隠すとペインのヘッダーに**目のアイコン**が出るので、それをクリックすると隠した Bot が薄い表示で元の位置に現れ、右クリック → **Unhide Bot** で戻せます。隠した Bot は通知を出しませんが、未読は静かにたまっていき、何かあったことが分かるように目のアイコンに点が付きます。隠したかどうかは Bot のプロファイルのメタデータに保存されるので、そのバックエンドにつないだどのデスクトップでも同じように隠れています。

:::note 正式な Bot Chat はずっと続くチャット
Bot の正式なチャットの中で `/new`（や `/reset`）と打つと、そこまでの関係が使い捨てのセッションに分岐してしまいます。Bot モードが「起きない」と約束しているのは、まさにこれです。そこで入力欄はそれを `/compact` に振り替えます。作業中の文脈だけ新しくして、会話そのものは同じまま続きます。同じプロファイルの通常のセッションでは、`/new` を今までどおり自由に使えます。
:::

## Bot を作る {#creating-a-bot}

一覧で **New Agent** を押します。手早く作るなら **Name**、**Title**、**Description** の 3 つを埋めるだけで、数秒で Bot ができあがり、新しい Bot Chat の最初のメッセージとして自己紹介します。

**Advanced** を開くと、設定できることが全部出てきます。

- **既存プロファイルから複製** — 別の Bot の設定・スキル・SOUL・記憶を引き継いで始めます。まっさらから作りたいときは **Fresh profile** を選びます。
- **Create empty** — 同梱のスキルをまるごと省いて、最小構成のプロファイルにします。
- **モデルとプロバイダの固定** — その Bot 専用のモデルを与えます。Hermes が知っているプロバイダとモデルの組み合わせならどれでも使え、別々のモデルで動く Bot を並べておけます。未設定のままにすると、起動時のプロファイルの設定を引き継ぎます。
- **Custom SOUL.md** — その Bot の人格と、常に守らせたい指示です。
- **スキル単位・ツールセット単位・MCP サーバ単位の有効化** — その専門役に必要な機能だけを選んでチェックします。
- **鍵の共有** — 既定では、新しい Bot はメインのプロファイルと 1 つの OAuth／トークンのプールを共有するので、認証情報を更新し合ってお互いを無効にしてしまうことがありません。（古いゲートウェイでは共有ではなく認証情報を複製します。動作はしますが、別々に分かれます。）

### どの端末に置くかを選ぶ（"Create on"） {#choosing-which-machine-it-lives-on-create-on}

[Settings → Connections](/hermes/docs/user-guide/multi-connection-desktop/) に接続先を 2 つ以上登録していると、New Agent のダイアログに **Create on** の選択欄が増えます。端末を選ぶと、プロファイルは**その**端末のバックエンド側に作られ、いま開いているウィンドウのゲートウェイは切り替わりません。作られた Bot は Connections の Bot として一覧に現れ（同じ名前が複数の端末にあるときは `@name-device` という形の呼び名が付きます）、その Bot と話すと処理はその端末側に流れます。

接続先が 1 つだけの場合（たいていはこちらです）この選択欄は出ず、いまつないでいる端末に Bot が作られます。以前と同じ動きです。

離れた端末に作るときの注意点です。

- **複製元**は*その端末側*のプロファイル（`default`）です。離れた端末には、手元のプロファイルはありません。
- Capabilities タブはその端末のバックエンドに接続したままになるので、作成中に設定したスキル・ツール・MCP サーバは、Bot が住むことになる端末に届きます。（古いデスクトップ版では、離れた端末が相手のときは下書き用の Skills／Tools／MCP のチェックリストに切り替わります。どちらの場合も、参照するのはその端末のカタログです。）
- ダイアログをキャンセルすると、作りかけのプロファイルは、作られた側の端末で破棄されます。

**Edit Profile**（Bot を右クリック）を選ぶと、動いているプロファイルに対して同じ画面をいつでも開き直せます。アバター、タイトル、説明、モデルの固定、スキル、ツールセット、MCP サーバ、SOUL.md の全文を編集できます。

**Duplicate**（右クリック）は Bot を丸ごと複製します。設定、スキル、SOUL.md、記憶、見た目まで引き継ぎます。**Delete Profile** は完全に削除します。デスクトップのプロファイルメニューと同じ、取り消せない操作の確認をはさみます。既定のプロファイルは削除できません。

## アバター {#avatars}

どの Bot にも顔が付きます。

- **Blob faces**（既定） — Bot の名前から決まる、やわらかい体の顔です。同じ名前なら同じ顔がずっと続きます。New Agent で名前を打っている間、顔がその場で追従します。**Randomize** を押すと引き直し、**Lock face** を押すと名前を変えても気に入った顔のままにでき、6 種類のシルエット（round、organic、boxy、nub、cloud、sun）のどれかを固定しつつ、それ以外は名前から決めることもできます。
- **Geometric faces** — おなじみの 7 形状 × 10 色で、Bot が働いている間はまばたきしながら目が動きます。
- **画像のアップロード** — 好きな絵をそのまま使えます。
- **AI が描いた似顔絵** — 画像生成のバックエンドを設定してあれば、その場で生成できます（これは標準の `image.generate` RPC を使うので、手元のゲートウェイでも離れたゲートウェイでも動きます）。
- **ドット絵のペット** — [petdex ギャラリー](/hermes/docs/user-guide/features/pets/)の相棒が、Bot が働いている間アバターの横で跳ねます。ターミナルで `hermes pets` を実行するとギャラリーを見られます。

Bot の見た目・タイトル・説明はバックエンド側のプロファイルのメタデータに保存されるので、そのバックエンドにつないだどのデスクトップでも同じ姿で現れます。

## Routines {#routines}

**Routines** ペインは、繰り返す作業を、それをやる Bot に紐づけます。「毎朝メールをまとめて」という作業は、それを担当する Bot のすぐ隣に置かれます。このペインは Bots タブを開いている間だけチャットの横に並び、Sessions に戻ると引っ込みます（古いデスクトップ版では常に表示されたままです）。スケジュールは項目を選んでいく形で組み立てられ（まず頻度を選び、それから必要な詳細だけを指定します）、Advanced の欄では Hermes のスケジュール文字列を直接書けます。

Routines の正体は、`[bot:<name>] <routine>` という名前空間を付けた普通の [Hermes の cron ジョブ](/hermes/docs/user-guide/features/cron/)です。`hermes cron list` や本体の Cron ページにも出てきます。実行結果は Bot 自身のチャット履歴に残るので、その Bot と話すときに見るのと同じ場所に結果があります。

## グループとグループチャット {#groups-and-group-chats}

手元の Bot を右クリック → **Manage groups** で、いくつでもグループチャットに出し入れできます。既存のグループを個別に選ぶことも、その場で新しく作ることもできます。手元側の所属はバックエンドと同期されるプロファイルのメタデータに保存されるので、そのプロファイルについてどのデスクトップにも付いていきます。以前のグループを 1 つ持っている古いプロファイルも、そのまま動きます。Connections の Bot は New Group Chat の選択画面から参加し、その部屋の共有された状態の中では、どの端末のものかが分かる形で保持されます。

**部屋が付いていくのは、1 台のデスクトップではなくゲートウェイの方です。** それぞれの部屋の直近のやり取り・メンバー・画像・名前は、デスクトップがつないでいる**すべての**ゲートウェイの共有プロファイルメタデータに写されます。ゲートウェイごとに版が管理されるので、2 台のデスクトップが同時に書き込んでも、片方が上書きされるのではなく統合されます。同じゲートウェイに対して別の端末（自宅の LAN でも Tailscale でも、どこからでも）で Hermes Desktop を開けば、その部屋が履歴ごと現れますし、ゲートウェイだけにつないでいるクライアントからも見えます。部屋は内部に消えない識別子を持つので、名前を変えても変わるのはどこでも表示名だけで、解散すればその時オフラインだった端末も含めてすべてのクライアントから恒久的に消え、同じ名前で作り直せば本当に新しい部屋として始まります。ゲートウェイが落ちたり外されたりしても、失われるものはありません。つないでいた各デスクトップが部屋の全体を手元に持ち続け、つなぎ直したゲートウェイへあらためて流し込みます。（やり取りの全記録は各デスクトップの手元の保存領域に残り、共有側に写されるのは直近の履歴に限った投影です。）

グループは、Bot の 1 対 1 チャットと同じ、直近の活動順に並ぶ一覧の中に、独立した行として並びます。Bot がいくつのグループに入っていても 1 対 1 の行は 1 つのままで、グループごとに部屋の行ができ、メンバー数・直近メッセージのプレビュー・時刻・あなたの判断待ちかどうかが表示されます。

グループの行（2〜6 体の Bot）で **Open chat** を押すと、全員で相談する共有の部屋が開きます。

- あなたが発言すると、メンバーの手番が最大**3 巡**、順番に回ります。@メンションされた Bot が答えます（誰も名指しされていなければ全員が答えます）。それぞれの Bot は短く答えるか、何も言わずに見送り、1 巡まるごと誰も発言しなければその場は収束します。
- Bot は `@name` でお互いを呼び込み、本当に判断が要ることは `@user` であなたに投げます。そうなるとグループの行に **needs you** のバッジが出ます。
- 1 回の送信につき 10 メッセージ、3 巡までという上限があるので、部屋が延々と回り続けることはありません。
- メンバーはそれぞれ自分の `Group: <name>` セッションを持ち続けるので、部屋での文脈も他の会話と同じように残ります。
- **すべての Bot がすべての発言に答えるわけではありません。** 発言するかどうかはメンバー自身が決めます。付け足すことがあるときだけ答え、なければ見送ります。特定のメンバーを @ で名指しすれば、その巡はその相手だけになります。名指しした相手（あるいは言いたいことがある Bot）が話し、残りは黙っているのが普通の姿です。
- **部屋は端末をまたげます。** New Group Chat の選択画面では、登録済みのどの接続先からでも Bot を席に着かせられます。各メンバーの手番はそれぞれの端末で、その端末の `Group: <name>` セッションの中で動きます。端末をまたぐメンバーには部屋の中でも他のメンバーの記録の中でも端末名のバッジ（`dixie · Mac Mini`）が付き、区別用の `@name-device` という呼び名が部屋のメンションでも使えます。おかげで、2 つの端末にいる同じ名前のエージェントが混ざることはありません。

## Bot 同士のメッセージ {#bot-to-bot-messaging}

Bot は誰からの発言かを添えてお互いにメッセージを送り、あなたはどのチャットからでも仕事を渡せます。

- **@メンション** — どのチャットでも `@researcher have a look at this` のように打つと、いま話している Bot がそのメッセージを渡し、返事を待って、結果を報告します。メンションの名前は現在の一覧と照合されるので、メールアドレスや知らない `@` はそのまま素通りします。
- **名前を変えた Bot はタグも一緒に変わります** — 分かりやすい名前を付けると（チャットのヘッダーの鉛筆アイコン、または `hermes profile rename`）、その名前で呼べるようになります。*Research Buddy* というタイトルの Bot は `@research-buddy`（および `@researchbuddy`）に反応し、それは通常のチャットでもグループの部屋でも同じです。入力欄の `@` 補完は新しいタグを出しますが、以前のプロファイル名を打っても一致し、そちらも引き続き使えます。
- **端末をまたぐ @メンション** — 別の登録済み接続先にいる Bot をメンションすると（名前がぶつかるときは `@name-device` の呼び名を使います）、Connections の登録情報を通じて裏側で届きます。話している Bot はこの端末に留まったまま、デスクトップがメッセージを相手の端末へ回し、返事はそのエージェントからのものとして返ってきます。あなたのウィンドウのゲートウェイが切り替わることはありません。
- **ダイレクトメッセージ** — どの Bot Chat にも `message_agent` というツールが備わっています。Bot は `message_agent(target="researcher", message="…")` を呼んで仲間にメッセージを送ります。このツールは宛先を現在の一覧と照合し、送り主を示す `Message from 🤖 <sender> (@<sender>):` という前置きを自動で付け、相手の正式な Bot Chat に届けます。配達は**送りっぱなし**です。送った側は受け付けた合図を受け取ってその手番を終え、返事はあとから完了通知として届きます。メッセージは本物の引数として渡るのでシェルに解釈されるものが何もなく、引用符も `$(...)` もバッククォートも、書いたままの形で届きます。また、あなたの言葉をそのまま転送するのではなく、Bot が自分の言葉で文面を組み立てます。仲間の一覧は、名前だけでなく各プロファイルのタイトルと説明から取った**役割**まで含めて、すべての Bot Chat のシステムプロンプトに入っているので、Bot は誰が何をする役なのかを知ったうえで宛先を選べます。このツールがあるのは、Bot モードで管理されているインストールの正式な Bot Chat セッション**だけ**です。通常のチャット、グループの部屋のメンバーのセッション、CLI のセッションからは見えません。

バックエンドは、それぞれの Bot の正式な Bot Chat セッションに、プロンプトを組み立てる時点でこのやり取りの決まりを自動で教えます。仲間が CLI から画面なしで開いたときも同じです。この決まりの部分が入るのは正式な Bot Chat だけで、通常のセッションと SOUL.md には手が入りません。これは `config.yaml` の `agent.bot_mode_protocol` で制御します（既定は有効）。

```yaml
agent:
  bot_mode_protocol: true   # inject the bot-to-bot messaging protocol into canonical Bot Chats
```

:::note
Bot 同士の配達は実行のたびに処理されます。受け取る側の Bot は、次に動いたときにメッセージを拾います。会話の途中の Bot にその場で割り込むのは、これからの課題です。
:::

### Bot から端末をまたいで送るダイレクトメッセージ（`hermes peer`） {#bot-initiated-dms-across-machines-hermes-peer}

ある端末の Bot は、デスクトップを一切はさまずに、**別の端末のゲートウェイ**にいる Bot へメッセージを送れます。相手のゲートウェイを*ピア*として登録します（API サーバの URL と `API_SERVER_KEY` を指定します）。

```bash
hermes peer add spark --url http://spark.lan:8377 --key <API_SERVER_KEY>
hermes peer list
hermes peer dm spark < /tmp/dm.txt        # message body from a file (nothing shell-interpreted)
hermes peer dm spark/researcher < /tmp/dm.txt   # named profile on a multiplexed peer
```

`hermes peer dm` は、ピアがすでに動かしている API サーバを通じて、離れたエージェントの正式な Bot Chat にメッセージを届け、その場でエージェントの手番を 1 回動かし、返事を標準出力に表示します。手元で使う `hermes -p <bot> chat` を、そのまま端末をまたいだ形にしたものです。

ピアを登録すると、すべての Bot Chat に教えられる決まり（`agent.bot_mode_protocol`）にピアの一覧が自動で加わり、`message_agent` はピアの宛先をそのまま受け付けるようになります。`message_agent(target="spark/researcher", …)` のように書き、そのピアの主エージェント宛なら `target="spark"` とします。つまり、**あなたの bot たちは自分で学びます**。別の端末にも仲間がいることと、そこへの届け方を知るわけです。ピアを登録したり外したりすると、各 Bot Chat の決まりは次のメッセージのときに更新されます（capability epoch）。

前提条件です。相手の端末で `api_server` のゲートウェイが動いていて、強い `API_SERVER_KEY` が設定されていること。そこに届くかどうか（LAN、Tailscale、VPN）はあなたのネットワーク側の話です。この鍵は認証情報なので、`~/.hermes/.env` に `HERMES_PEER_<NAME>_KEY` として置きます。ピアの名前と URL は `config.yaml` の `bot_peers` の下に書きます。

## 端末をまたぐ Bot {#bots-across-machines}

**Settings → Connections** に複数のバックエンド（手元のランタイム、離れたゲートウェイ、SSH ホスト、Hermes Cloud のインスタンス）を登録すると、一覧には**すべての**接続先の Bot が出続けます。SSH の接続先は相手側で何も起動せずに一覧を取得し、たまたま届かない端末も消えずに最後に分かっていた行を残します。同じプロファイル名が複数の接続先にあるときは、`@name-device` の形（たとえば `@research-homelab`）で区別されます。Bot のチャット・セッション・記憶・定期タスクは、そのプロファイルを持っている端末側にあります。

Connections の Bot をクリックしても、あなたのウィンドウがその端末に移ることは**ありません**。自分のチャットにいたまま `@mention` するか、グループチャットに座らせるか、**Create on** の選択欄でその端末に新しいエージェントを作ります。クラウドと手元のエージェントは、こうして 1 つの一覧を共有します。Hermes Cloud のインスタンスと自分のデスクトップを（たとえば Tailscale や SSH 越しに）登録すれば、それぞれの Bot がメッセージを送り合い、同じ部屋に座れます。各エージェントの作業は、それぞれの端末で動きます。

複数接続の詳しい手引きは、[Connecting Desktop to Many Hermes Instances](/hermes/docs/user-guide/multi-connection-desktop/) を参照してください。

## 止め方 {#turning-it-off}

Bot モードは同梱のデスクトップ用プラグインです。**Settings → Plugins → Bots** で切ると、一覧も Routines ペインも入力欄の中間処理もその場で登録解除されます。再起動は要りません。どちらの状態でも、あなたのプロファイル・セッション・cron ジョブには手が入りません。Bot モードがデータを持つことはなく、表示しているだけです。

もう 1 つ、正式な Bot Chat を通常のサイドバーのセッション一覧から隠して、Bots ペインの中だけに出す設定もあります。（これは本体のセッション非表示フラグを使います。古いゲートウェイでは、チャットはそのまま表示され続けます。）

## CLI でも同じことができる {#cli-parity}

Bot はプロファイルなので、すべてにターミナルでの同等の操作があります。

| Bot モードでの操作 | シェルからの操作 |
| --- | --- |
| Bot と話す | `hermes -p <bot> chat` |
| Bot のファイル・スキル・記憶 | `~/.hermes/profiles/<bot>/` |
| Routines | `hermes cron list`（`[bot:<name>] …` という名前のジョブ） |
| プロファイルの作成・確認 | `hermes profile create`, `hermes profile list` |

土台になっている仕組みは [Profiles](/hermes/docs/user-guide/profiles/) を、CLI の全項目は [Profile Commands](/hermes/docs/reference/profile-commands/) を参照してください。
