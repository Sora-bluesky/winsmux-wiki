# Hermes Desktop {#hermes-desktop}

Hermes のデスクトップアプリは、CLI やゲートウェイで使うのと**同じ**エージェントを中心に作られたネイティブアプリです。設定も、API キーも、セッションも、スキルも、記憶も同じものを使います。別製品でも軽量な複製でもありません。同じ Hermes Agent の中核と設定をそのまま使い、現代的で丁寧に設計された画面から動かします。ターミナルで `hermes` を使ったことがあるなら、そこで整えたものはすでにここにありますし、ここでやったことはあちらにも現れます。

**macOS（Apple Silicon）、Windows、Linux** で動きます。対応状況の全体は[プラットフォームの対応状況](/hermes/docs/getting-started/platform-support/)を参照してください。

:::tip どの窓口がどれなのか
Hermes には、同じエージェントにつながる窓口がいくつかあります。

- **デスクトップアプリ**（このページ） — 対話・設定・管理のために作り込まれた画面を持つ、ネイティブアプリです。
- **CLI**（`hermes`）と **[TUI](/hermes/docs/user-guide/tui/)**（`hermes --tui`） — 端末の中の窓口です。
- **[Web ダッシュボード](/hermes/docs/user-guide/features/web-dashboard/)**（`hermes dashboard`） — ブラウザーの管理画面です。任意で使える **Chat** タブは、疑似端末を通して TUI を埋め込んでいます。

その場に合うものを選んでください。状態は共有されるので、片方で始めたセッションをもう片方で続けられます。
:::

## 導入 {#install}

[Hermes Desktop の製品ページ](https://hermes-agent.nousresearch.com/desktop)からアプリをダウンロードするか、[Hermes Desktop の導入手順](/hermes/docs/getting-started/installation/)に従ってください。

すでに Hermes を導入しているなら、次を実行するだけです。

```bash
hermes desktop
```

いまの設定、キー、セッション、スキルがそのまま使われます。

## アプリに入っているもの {#whats-in-the-app}

デスクトップアプリは、対話を中心に据えた画面と、左の移動用サイドバーで構成されています。複数のエージェントとの会話を同時に扱い、メッセージ連携を設定し、成果物を作り、プロジェクトのフォルダー構成を眺め、複数のプロジェクトを並行して進められるように作られています。

サイドバーの選択は、フォーカスされている対話ペインに追随します。セッションのタブを開いたりフォーカスしたりすると、ページ側の強調表示は解除されます。カンバンのような追加ページも同様で、作業スペースがそのページの経路を保持していても解除されます。

### 対話 {#chat}

アプリの中心です。次のことができます。

- **応答のストリーミング** — エージェントが作業するあいだ、ツールの動きと、構造化されたツール呼び出しの要約が流れます。
- **Markdown の改行**は Markdown の意味づけに従います。行末の空白 2 つで強制改行になり、ふつうの改行は緩い改行のままです。メディアとプレビューの抽出は、取り除いた添付部分の外にあるテキストを保ちます。1 行目のコードのインデントや、閉じていないコードフェンスの空白も同様です。コードの表示とコピーは、先頭の空行、行末の空白、Markdown パーサーが出す末尾の空行を保ちます。
- **会話履歴はすべての窓口で同じ** — ここで始めたセッションは CLI や TUI で再開できますし、その逆もできます。
- **ファイルのドラッグ＆ドロップ** — 対話領域のどこにでも落とせば、次のメッセージに添付されます。
- **裏の下書きは独立して動きます** — 隠れている対話タブは、表示中の入力欄のカーソルや選択を動かさずに、自分の下書きを更新できます。
- **指示チップの操作** — URL のような操作できる参照にカーソルを合わせると、操作用の丸いボタンが現れます。少しの猶予があるので、チップからボタンへ移動するあいだに消えることはありません。ボタンの中で動いているあいだは表示され続けます。離れたあとは、関係のないポインターの動きで消えるのが遅れることはありません。操作をクリックしても、下書きの選択は保たれます。
- **右側のプレビュー欄** — Web ページ、ファイル、ツールの出力を横に並べて表示しながら、対話を続けられます。
- **アプリ内ブラウザーのコメントモード** — プレビューのブラウザーバーで **Annotate** をクリックし、表示中のページ上の要素をクリック（または範囲をドラッグ）してメモを書きます。保存したコメントは、番号付きのピンとしてページに残ります。ピンを保存してもターンは送られません。書き終えたら **Add N comments** を押すと、ピンごとに切り抜いた画面写真と、各コメントを名指しする短い指示文が入力欄に添えられます。送信は自分の手で行います。要素へのコメントには、その CSS セレクター、マークアップ、レイアウトに関わる計算済みスタイルが付くので、エージェントは画像から推測するのではなく、実際のソースの中からその要素を見つけられます。パスワードや隠しフィールドの値、キーやトークンに見える属性は、マークアップがページを出る前に伏せられます。数が多い場合は、コメントがページのどの部分にあるかでまとめられて届くので、20 件あまりのコメントが 1 件ずつの作業ではなく、数個の仕事の塊になります。まとまりはそれぞれ別の DOM 部分木なので、たいてい別々のファイルに触れることになり、それが並行して作業を割り振っても安全な理由です。ピンの番号は 1 つ消しても崩れませんし、対話を切り替えると積み上がったものは消えます。
- **入力欄の履歴と待ち行列の編集** — 空の入力欄で上下の矢印キーを押すと、以前の指示文を呼び出して使い回せます。送信待ちに並べたメッセージは、送られる前に編集できます。ターンが待ち行列にある状態で Stop（または Esc）を押すと待ち行列が止まり、入力欄の上に展開されます。そこから再開するか、個別に送信・編集・削除できます。
- **入力欄の上のタスク進捗** — Tasks の見出しを展開すると、各段階を確認できます。長い一覧も入力欄の上で高さが抑えられるので、会話を動かさずに一覧の中をスクロールして最後のタスクまで見られます。
- **会話のタイムライン欄** — 長い対話では、記録の端に沿って指示文 1 つにつき 1 つの目印が並ぶ細い欄が出ます。カーソルを合わせると指示文の一覧が開き、クリックすればその地点へ直接飛べます。（対話が何ターンかたまると現れます。）
- **読んでいた位置の記憶** — セッションに戻ると、常に最新のメッセージへ飛ぶのではなく、保存された「最下部からの距離」が復元されます。最下部に置いたままのセッションは、新しい出力を追い続けます。**Scroll to bottom** で最新の位置に戻れます。位置はこのデスクトップ環境の手元の保存領域に置かれ、バックエンド経由で同期されることはありません。
- **ページ内検索** — **Cmd/Ctrl+F** で検索バーが開き、表示されている対話の記録を検索します。Enter と Shift+Enter（バーが開いているあいだは Cmd/Ctrl+G と Cmd/Ctrl+Shift+G でも）で一致を順に移動し、Esc で閉じます。

非同期の cron や委任の完了は、たたまれたタイムラインの開閉要素として現れます。完了のラベルを開くと、結果の本文（ジョブの出力を含む）が Markdown として読めます。長い報告は、その開閉要素の中でスクロールします。タスクの指示文や配送の封筒部分は、報告の中身としては表示されません。

#### ステータスバー {#status-bar}

対話の下端に並ぶバーは、セッションの状態をその場で示し、設定を開かずに素早く操作できるようにします。

- **セッションごとの YOLO 切り替え** — このセッションだけ YOLO を入り切りできます（TUI と同じです）。YOLO は危険なコマンドの承認プロンプトを飛ばすので、何を外しているのか理解して使ってください。[セキュリティ → YOLO モード](/hermes/docs/user-guide/security/#yolo-mode)を参照してください。
- **コンテキスト使用量のメーター** — セッションのコンテキストウィンドウが何 % 埋まっているかを示します。クリックすると **Context Usage** のポップオーバーが開き、分類ごとのトークンの内訳（システムプロンプト、ツール定義、スキル、記憶、ルール、MCP、サブエージェントの定義、そして会話そのもの）が見えるので、圧縮が始まる前に何がウィンドウを食っているのかが分かります。
- **キャッシュ命中率と 1 秒あたりのトークン数** — 既定では非表示です。右クリックのメニューから表示できます。キャッシュ命中率は、このセッションの入力トークンのうちプロバイダーのプロンプトキャッシュから返された割合です（キャッシュされたトークンは安いので、高いほど安上がりです。セッションが温まるにつれて安くなっていく様子が見られます）。1 秒あたりのトークン数は、直近 10 回のモデル呼び出しで平均した出力の速さです。どちらもターンの最中に随時更新されます。
- **表示項目のカスタマイズ** — ステータスバーを右クリック（**Show in status bar**）して、何を出すかを選べます。コンテキストのメーター、キャッシュ命中率、1 秒あたりのトークン数、作業スペース、モデル、承認、ターンとセッションの時間、ターミナル、Command Center、バックエンドのバージョン、ほか多数です。バー自体を隠すこともできます（**Cmd/Ctrl+Shift+S** で切り替わります）。

同梱の手元バックエンドではなく、別の端末で動く Hermes に対して対話しますか。下の[リモートのバックエンドにつなぐ](#connecting-to-a-remote-backend)を参照してください。リモートで動かすダッシュボードへの接続のしくみ全体（認証の関門、`/api/ws` の対話用ソケット、WebSocket の切断コードの切り分け）については、[Web ダッシュボード → Hermes Desktop をリモートのバックエンドにつなぐ](/hermes/docs/user-guide/features/web-dashboard/#connecting-hermes-desktop-to-a-remote-backend)を参照してください。

#### フォント {#fonts}

**Settings → Appearance** には、互いに独立した 2 つのフォント設定があります。どちらもプロファイルごとに `config.yaml` へ保存されます。

- **Chat Font**（`desktop.font_family`）— 対話と、アプリのそれ以外の画面に使われます。OpenDyslexic や Atkinson Hyperlegible のような読みやすさを重視した書体は、システムに導入すればすぐに使えます。選んだ書体の後ろには使用中のテーマのフォント指定が控えているので、足りない文字も表示されます。空欄にするとテーマのフォントになります。
- **Terminal Font**（`terminal.font_family`）— 組み込みのターミナルのペインに使われます。Nerd Font なら、ここでシェルのアイコンが描画されます。空欄にすると同梱の JetBrains Mono になります。

#### リポジトリの検出 {#repository-discovery}

Hermes Desktop は、ホームディレクトリを一定の深さまで走査して、Projects サイドバー用に手元の Git リポジトリを見つけます。この動きはプロファイルごとに **Settings → Workspace** から、または `config.yaml` から変えられます。

```yaml
desktop:
  repo_scan_enabled: true
  repo_scan_roots: []
  repo_scan_exclude_paths: []
```

- `repo_scan_enabled: false` にすると、ファイルシステムの走査を完全に止めます。そのプロファイルのディスク検出のキャッシュ行は消えますが、明示的に登録したプロジェクトと、意図して開いた Hermes のセッションから割り出したリポジトリは残ります。
- `repo_scan_roots` にフォルダーの一覧を設定すると、走査範囲を絞れます。空の一覧なら、既定のホームディレクトリ走査のままです。
- `repo_scan_exclude_paths` には、部分木ごと丸ごと飛ばしたいフォルダーを設定します。

これらの値を変えると、そのプロファイルのディスク検出キャッシュだけが無効になり、方針に沿った再取得が始まります。**Hide from sidebar** は、項目ごとに手で整える別の操作のままです。

#### モデルを選ぶ {#choosing-a-model}

モデルの選択欄は**入力欄**の中、マイクのすぐ左にあります。クリックするとモデルを切り替えられます。モデルの行にカーソルを重ねると、その設定（思考、推論の強さ、高速）が出ます。その隣には**推論ピル**があり、使っているモデルの推論の強さ（`Med`、`High`、…）を表示します。ここから同じ設定を直接開けるので、モデルの行を探さなくても推論の強さを変えられます。カタログで推論の調整ができないとされているモデルでは、このピルは表示されません。

- **入力欄の選択欄は表示上の状態で、既定値には一切触れません。** 端末ごとに手元で覚えられ、新しい対話や再起動をまたいで**そのまま引き継がれます**。既定に戻ることはありません。一度選べば、次の `Cmd/Ctrl+N` はそのモデルで開きます。対話が動いているときにモデルを切り替えると、変更はその**いまの対話**の範囲になります。どちらの場合も、選択はセッションの作成や切り替えのときに一緒に運ばれ、プロファイルの既定値へ書き込まれることは**ありません**。例外が 1 つあります。`model.default` や `model.provider` がまだ設定されていない新しいプロファイルでは、最初の選択が保存されます。再起動時に、たまたま残っていた API キーの環境変数へ落ちてしまうのではなく、実体のある既定値を持たせるためです。保存の規則は `/model` と同じです（`model.persist_switch_by_default`）。既定値を意識して変えたいときは **Settings → Model** を使ってください。（[プロファイル](#sessions--profiles)を切り替えると、そのプロファイル自身の既定値で入れ直されます。）
- **既定値は Settings → Model で設定します。** この「主」モデルが、**プロファイルごとの全体の既定値**です。新しい対話、cron、サブエージェント、補助タスクはここから始まりますし、これを書き込むのはここだけです。[プロファイル](#sessions--profiles)はそれぞれ自分の既定値を持ちます。
- **モデルごとの強さと高速モードの記憶。** デスクトップアプリでは、モデルごとに推論の強さと高速モードの選択を覚えていて、そのモデルを選ぶたびにセッションへ適用し直します。これはデスクトップ側の便宜であって、cron やサブエージェントを変えるものではありません。
- **対話の途中で切り替えるとプロンプトキャッシュが消えます。** 動いている対話の中でモデルを切り替えると、次のメッセージは会話全体を割引なしの入力価格で読み直します（プロバイダーのプロンプトキャッシュはモデルごとに分かれているためです）。たまになら問題ありません。長い対話では、行ったり来たりするより、新しいモデルで新しい対話を始めたほうが安く済むことが多いです。

### ファイルブラウザー {#file-browser}

アプリを離れずに作業ディレクトリを眺め、中身を確認できます。エージェントがファイルを読み、書き、直していく様子を追うのに便利です。最初のプロジェクトディレクトリは `hermes desktop --cwd <path>`（または `HERMES_DESKTOP_CWD` 環境変数）で指定します。

### 成果物 {#artifacts}

リモートのゲートウェイにつないでいるとき、ファイルの成果物を開くと、そのゲートウェイ経由でダウンロードされます。使われるのは、その成果物が生まれたプロファイルとセッションです。相対パスはセッションに保存された作業ディレクトリを基準に解決され、ホーム基準のパスはゲートウェイ側のホームを使います。デスクトップ側の端末のホームは使いません。Windows 形式の相対パスもスラッシュ区切りのパスと並んで認識され、file URI はドライブやネットワーク共有の情報をゲートウェイが解釈できる形で保ちます。セッションや作業ディレクトリが見つからない場合は、別の手元のファイルを選ぶのではなくエラーになります。

**Artifacts** の画面は、セッションが生み出したもの（**画像、ファイル、リンク**）を、検索して見て回れる 1 つのギャラリーに集めます。サイドバー、コマンドパレット（**Artifacts — Browse generated outputs**）、または自分で割り当てた `nav.artifacts` のショートカットから開けます。最近のセッションの出力は自動で索引化されます。どの成果物にも、それを生んだセッションが示され、その対話へ戻れます。画像とファイルはプレビューで開き、ダウンロード、ブラウザーで開く、コピーの操作ができます。

### ウィンドウ、タブ、ペイン {#windows-tabs-panes}

このアプリは、いくつものことを同時に進めるために作られています。

- **タブ** — **Cmd/Ctrl+T** で新しいセッションのタブが開きます。**Ctrl+Tab** と **Ctrl+Shift+Tab** でセッションを順に巡り、**Ctrl+1…9** で最近のセッションへ位置指定で飛べます。**Cmd/Ctrl+W** でフォーカス中のタブを閉じ、**Cmd/Ctrl+Shift+T** で最後に閉じたものを開き直します。
- **複数のウィンドウ** — **Cmd/Ctrl+Shift+N** で新しいウィンドウが開きます。どのセッションもコンテキストメニュー（**New window**）やコマンドパレットから切り出せます。切り出したウィンドウは、全体のサイドバー無しでその 1 つの対話だけを表示するので、長時間動くセッションを別のモニターに置いておくのに向いています。エージェントの出力は、そのセッションを表示しているすべてのウィンドウへ流れます。
- **ペイン** — **Cmd/Ctrl+B** で左のサイドバー、**Cmd/Ctrl+J** で右のサイドバーを切り替え、**Cmd/Ctrl+\\** でサイドバーの左右を入れ替えます。

### ターミナル {#terminal}

右のサイドバーには、ファイルブラウザーの隣に本物のターミナルがあります。

- **Ctrl+`** でターミナルが表示されます（1 つも無ければ開きます）。**Ctrl+Shift+`** でもう 1 つ増やせます。複数のターミナルはタブの列に積まれ、**Ctrl+Shift+↓/↑** で行き来し、**Ctrl+Shift+W** でいま使っているものを閉じます。
- **隠れていてもシェルは生き続けます。** パネルを閉じたり隠したりしてもシェルは終了しません。開いているターミナルは、明示的に閉じるまで、スクロールバックと実行中のプロセスをそのままに保たれます。
- **Add to chat** — ターミナルの出力を選択して、次のメッセージの文脈として入力欄へ送れます。

### 動いているサブエージェント {#live-subagents}

委任したワーカーが動いているあいだ、入力欄の上に **Subagents** の枠が現れ、その数、タスク名、経過時間、直近の動きを表示します。表示されるのは 3 つまでで、見出しを展開すると全員の一覧が出ます。ワーカーを選ぶと詳細と、**Steer** や **Stop** の操作が使えます。この枠は分割ペインの中も含め、それぞれの対話に属します。Steer は、指示が節目に向けて待ち行列に入ったことを知らせるもので、子がすでに読んだという意味ではありません。[サブエージェントを見張る](/hermes/docs/user-guide/features/delegation/#monitoring-running-subagents-agents)を参照してください。

### Git のレビューと worktree {#git-review-worktrees}

Git リポジトリの中で動いているセッションには、ソース管理の画面が組み込まれています。

- **レビューのペイン** — **Cmd/Ctrl+G** で作業ツリーのレビューペインを開閉します。ブランチと先行・遅れの状態、変更されたファイル（一覧表示かツリー表示）、そして **Uncommitted**、**Branch**、**Last turn**（直近のターンでエージェントが変えた分だけ）に絞った差分が見られます。ファイルの staging と解除、変更の取り消し、コミットメッセージの記述（**Generate commit message** も使えます）ができ、**Commit** や **Commit & Push** を実行できます。GitHub CLI（`gh`）を使う **Create PR** もありますし、**Ask Hermes to open PR** で一式をエージェントに任せることもできます。ブランチの作成と切り替えもここからできます。
- **worktree** — **Cmd/Ctrl+Shift+B**（またはサイドバーのプロジェクトで **New worktree**）を選ぶと、新しいブランチの上に Git の worktree が作られ、いまのチェックアウトに触れずに、エージェントがリポジトリの並行した複製で作業できます。worktree はプロジェクトの下に独立した列として現れます。取り除くときは、worktree のディレクトリを削除する（ブランチは残ります）か、列を隠してディスク上には残すかを選べます。コミットしていない変更があるときは強制するかどうかも選べます。

### 記憶のグラフ {#memory-graph}

**Memory Graph**（コマンドパレット → *Memory Graph*、またはステータスバーの項目）は、Hermes が自分のために学んだことを示す対話的な地図です。スキルと記憶が、拡大縮小できるノードのグラフとして時系列付きで並び、**All / Used / Learned** で絞り込めます。共有の操作から、地図の配置を小さなコードとして書き出して誰かに渡せますし（配置だけで、記憶やスキルの本文は含まれません）、同じ形でコードを読み込めます。

### Quick Entry {#quick-entry}

Quick Entry は、**システムのどこからでもグローバルなホットキーで呼び出せる**小さな入力欄です。主ウィンドウに切り替えることなく（開いてすらいなくても）指示を投げられます。**Settings → Advanced → Quick Entry** で有効にしてください。既定のショートカットは **Ctrl/Cmd+Shift+Space** で、自分で決めることもできます（修飾キーが最低 1 つ必要です）。その組み合わせを他のアプリがすでに使っている場合は、設定の行がそれを知らせるので、別のものを選べます。

### 音声 {#voice}

Hermes に話しかけ、返事を聞けます。他の場所でも使える[音声モード](/hermes/docs/user-guide/features/voice-mode/)と同じものです。macOS では、OS がマイクの利用許可を一度だけ尋ねます。

### HUD モード {#hud-mode}

**⌘/Ctrl+Shift+H**（またはタイトルバーのボタン）を押すと、対話が枠の無い、常に最前面の浮かぶバーとして切り離され、いま作業しているものの上に乗ります。アプリのウィンドウは脇へどきますが、HUD は動いている会話と入力欄を保ちます。どこに置くかが文脈になります。バーの位置から、Hermes はどのアプリと画面について聞かれているのかを判断するので、「これ」「ここ」「そのページ」が、その下にあるものを指すようになります。

- **バーを動かす** — macOS と Windows では、入力欄のどこかを**少し長押し**してからドラッグします。Linux と X11 では、**Ctrl** を押しながら主ボタンでドラッグすると即座につかめます（選択されたテキストの上でも同じです）。長押しも引き続き使えます。仮想デスクトップを切り替えるショートカットを押すときにつかんだままにすると、HUD を別の仮想デスクトップへ連れて行けます。ネイティブの Wayland では、入力欄のバーがコンポジターのドラッグ用の取っ手になります（アプリが自分のウィンドウ位置を決められないため、これが動かす唯一の方法です）。
- **大きさを変える** — バーの端や角をドラッグします。反対側の端は固定されたままです。ネイティブの Wayland では、コンポジターがアプリに最上位ウィンドウの位置決めを許さないため、右端と下端だけが使えます。
- **配置を戻す** — バーにある破棄の操作で、既定の大きさと（X11、macOS、Windows では）位置に戻ります。保存された大きさのせいで HUD が使えなくなったときに使ってください。
- **ポインターの位置へ寄せる** — **⌘/Ctrl+Shift+G**（どのアプリからでも効くグローバルなホットキーです）で、HUD がカーソルのある場所へ飛びます。ネイティブの Wayland では何も起きません。配置はコンポジターが握っているためです。
- **抜ける** — バーの終了ボタンをクリックするか、**⌘/Ctrl+Shift+H** をもう一度押すか、HUD にフォーカスがあるときに **⌘/Ctrl+W** を押します。セッションはそのままに、アプリのウィンドウが前面に戻り、入力欄にカーソルが置かれた状態になります。

#### Linux と Wayland {#linux-wayland}

Electron 20 以降は、Wayland のセッション上ではすでにネイティブの Wayland クライアントとして動きます。ドラッグ、クリックの透過、大きさの変更は、その経路で動作します。

**Hyprland**（Omarchy を含みます）では、HUD がマップされたあとにコンポジターの IPC を通して浮かせて固定します。そうしないと、Hyprland は他のウィンドウと同じようにタイル配置してしまい、`always-on-top` は無視され、コンポジターのドラッグも効きません。追加のウィンドウ規則は不要です。

一部のコンポジター（特に COSMIC）は、ネイティブの Wayland ウィンドウに対して `always-on-top` を無視します。そこで固定を効かせたい場合は、XWayland の下でアプリを動かしてください。

```yaml
desktop:
  ozone_platform_hint: x11
```

これは起動時に `ELECTRON_OZONE_PLATFORM_HINT` へ渡されます（明示的に設定した環境変数のほうが優先されます）。引き換えとして、X11 はマウスを無視したウィンドウを元に戻せないため、HUD はクリックが透過しない実体のあるウィンドウのままになります。KDE の環境では、X11 の ozone バックエンドでキーボードが壊れるという報告もあります。常に最前面が必要でなければ、ヒントは `auto` のままにしてください。

#### WSLg（WSL2 から Windows の GPU を使う） {#wslg-windows-gpu-from-wsl2}

`hermes gui` を WSL2 の中で実行し、`/dev/dxg` があって Mesa の `d3d12_dri.so` が導入されている場合、起動側は Electron 向けに `GALLIUM_DRIVER=d3d12` を設定するので、llvmpipe のソフトウェア描画ではなく Windows の GPU で描画されます。環境に `GALLIUM_DRIVER`、`MESA_LOADER_DRIVER_OVERRIDE`、`LIBGL_ALWAYS_SOFTWARE`、`LIBGL_DRIVERS_PATH` を明示していれば、それには手を触れません（たとえば `GALLIUM_DRIVER=llvmpipe hermes gui` ならソフトウェア描画のままです）。

### 設定と初回の案内 {#settings-onboarding}

プロバイダー、モデル、ツール、認証情報を、YAML を編集するのではなく実際の画面から管理できます。初回の案内は、数秒で最初のメッセージまで連れて行きます。設定の画面は、プロバイダーとキー、モデルの選択、ツール群の設定、MCP サーバー、ゲートウェイ、セッション管理をカバーします。

- **プロバイダーの設定画面** — 推論プロバイダーを管理する専用の場所で、プロバイダーごとにサインインして認証情報を保存する、アカウントと API キーの操作面があります。アカウントと API キーは、設定の **Applies to** の選択を共有します。認証情報の読み取りと編集、OAuth アカウントの削除、ここから始めたサインインは、動いている対話のプロファイルではなく、選ばれたプロファイルを対象にします。サインインの流れは、認証情報の保存とモデルの選択のあいだ、その対象を保ち続けます。**Applies to** を変えると、保存していない認証情報の下書きは破棄されます。サインインを閉じると待ち受けは中止され、遅れて届いた結果は無視されます。すでに送られた認証情報の書き込みは、元のプロファイルで完了することがあります。外部で管理される CLI の認証情報は、その CLI 自身のものを使うので、このプロファイル選択の対象外です。この画面の **Local Models** の項目では、端末上で動く llama.cpp のランタイムを導入・管理できます。[ローカルモデル](/hermes/docs/user-guide/local-models/)を参照してください。
- **メニューにはすべてのプロバイダーとモデルが並びます** — 画面には、プロバイダーの全一覧と `hermes model` が知っているすべてのモデルが出ます。厳選された一部ではなく、CLI が見ているのと同じ品ぞろえから選べます。
- **xAI Grok の OAuth** — Grok は起動画面で一級の OAuth プロバイダーとして扱われます。他の OAuth プロバイダーと同じく、ブラウザーの流れでサインインしてください。
- **ツールのバックエンドを画面から導入** — ツールのバックエンドの導入後の手順を、端末に降りずにアプリから直接実行できます。
- **ターミナルのフォント選択** — **Settings → Appearance** で、導入済みのフォントを選べます。`MesloLGS NF` のような Nerd Font なら、対話用とエージェント用のどちらのターミナルでも Powerlevel10k の区切りやアイコンが描画されます。この設定はプロファイルごとに保存されます。
- **起動時に前回の対話を開く** — 既定では、冷えた状態からの起動でも前回の続きから始まります。常に新しい対話で始めたい場合は **Settings → Appearance** で切るか、`config.yaml` に `display.resume_last_session: false` を設定してください。ディープリンクや明示的な行き先は、どちらの設定でも上書きされません。
- **補助モデルの警告** — 補助タスク（題名付け、要約などの手伝い）が別のプロバイダーに固定されたまま、主モデルを新しいプロバイダーへ切り替えようとすると、アプリが警告します。知らないうちに 2 つのプロバイダーへ仕事が分かれてしまうのを防ぐためです。
- **仕事ごとの推論の強さ** — **Settings → Model → Auxiliary models** の各行には、プロバイダーとモデルの選択の隣に推論の選択欄があります。段階を選ぶか、**Off**、または **inherit · main model effort**（既定値で、その仕事の上書きを取り除きます）を選べます。`config.yaml` の `auxiliary.<task>.reasoning_effort` に保存され、`hermes model` が書くのと同じキーです。設定すると行の要約にも表示されます。圧縮や題名付けのように頻繁に動く手伝いは推論を低くするか切り、主エージェントは高いままにする、といった使い方ができます。
- **VS Code Marketplace のテーマ** — 内蔵のテーマの組み合わせに加えて、外観の設定から VS Code Marketplace をその場で検索できます。好きな配色テーマを選ぶと、アプリがダウンロードして変換し、デスクトップ用のテーマとして導入します。同じ取り込み機能はコマンドパレット（*Install theme*）からも使え、取り込んだテーマは外観の設定から削除できます。
- **コンピューターを起こしたままにする** — **Settings → Advanced → Keep computer awake** は、端末がスリープに入るのを止めるので、長時間や夜通しのエージェントの実行が続きます（画面は暗くなることがあります）。これは端末ごとの設定です。

初回の案内は、統一された重ね表示の設計体系で作り直されました。**Choose provider later** を選べば、プロバイダーの設定を飛ばして先にアプリの中へ入れます。

#### プロファイルごとの設定: 「Applies to」の適用範囲 {#per-profile-settings-the-applies-to-scope}

[プロファイル](/hermes/docs/user-guide/profiles/)が 2 つ以上あるとき、設定ファイルに紐づく設定ページ（**Model、Workspace、Safety、Memory & Context、Voice、Chat、Advanced、Tools & Keys**）と、**Messaging** の重ね表示の上部に、共通の **Applies to** のチップ列が出ます。ここで、編集がどのプロファイルに効くかを選びます。

- 既定の選択は**動いているプロファイルに追随します**。これは以前とまったく同じ挙動で、使っているプロファイルを編集することになります。
- 別のプロファイルを選べば、アプリ全体を切り替えずに*そのプロファイルの*設定を見て編集できます。設定ページを移動しても選択は保たれます。
- アプリの動作中のプロファイルを切り替えると選択欄は初期化されるので、以前に選んだプロファイルへ編集が黙って入り続けることはありません。
- プロファイルが 2 つ未満のときは、チップ列そのものが隠れます。

（Gateways のページはプロファイルの扱いが違い、**Per-profile overrides** の小見出しで扱います。Capabilities と Scheduled Jobs の画面は、それぞれ独自の適用範囲の選択欄を持ちます。）

### 管理用の画面 {#management-panes}

端末に降りずに済むよう、Hermes の広い管理機能もアプリの中に出ています。

- **Skills** — [スキル](/hermes/docs/user-guide/features/skills/)を眺め、導入し、管理します。Skills のタブには、導入済みのスキルが有効・無効の切り替えとともに並び、その下に Hermes に同梱される任意スキルの全一覧が出ます。各項目には **Install** ボタンがあり、押して終われば導入済みの一覧へ移ります。
- **記憶のグラフ（Star Map）** — 対話の中で `/journey`（別名 `/learning`、`/memory-graph`）と入力すると、学んだスキルと記憶が時間とともに並ぶ対話的な星座図が開きます。再生用のつまみも付いています。ノードはそのパネルから編集・削除できます（スキルは保管され、記憶は削除されます）。[学びの道のり](/hermes/docs/user-guide/features/memory/#learning-journey-journey)を参照してください。
- **Cron** — [予定されたジョブ](/hermes/docs/reference/cli-commands/#hermes-cron)を見て管理します。
- **Profiles** — [Hermes のプロファイル](/hermes/docs/user-guide/profiles/)（設定・スキル・セッションが分かれたもの）を切り替えます。
- **Messaging** — ゲートウェイのチャンネルを設定します。Telegram には **Quick setup** のカードがあります。**Create with QR** をクリックし、Telegram でコードを読み取る（またはリンクを開く）と、Hermes がボットを作り、許可一覧に使う利用者 ID を見つけ、認証情報を保存し、ゲートウェイの再起動までを代わりに済ませます。認証情報の保存、消去、有効化の切り替えをしたときは、ゲートウェイが実際に再起動するまで、ページに **Restart now** の帯が出たままになります。再起動に失敗しても帯は残るので、やり直すか、手で再起動できます。
- **Agents** と **Command Center** — 複数エージェントの作業を束ねる画面です。

### Bot Mode（同梱） {#bot-mode-built-in}

**Bot Mode** はアプリに同梱され、既定で有効です。「エージェント 1 体につき対話 1 つ」
の名簿で、[Hermes のプロファイル](/hermes/docs/user-guide/profiles/)がそれぞれ 1 体のボットとして現れます。ボットは自分の
アバター（幾何学的な顔、アップロードした画像、AI が生成した肖像、ドット絵の
ペット）と、自分の正式な **Bot Chat** の会話、そして自分の **Routines**
（Hermes の cron に支えられた繰り返しタスク）を持ちます。名簿は左の
サイドバーで会話の隣のタブとして置かれ、**Sessions | Bots** のタブ列に
なります。セッションの一覧の下に積まれた 2 つ目のペインではありません。以前の
積み重ね配置になっている環境は、一度だけ自動でタブ列へ移されます。自分の手で
ペインを配置している場合は、その配置には手を触れません。**Cronjobs**（Routines）
のペインは、Bots のタブが選ばれているあいだだけ対話の隣に接し、Sessions に
戻すと消えます（古いデスクトップ版では常に表示されたままです）。

新しいエージェントは名簿から作れます。
名前・肩書き・説明に加えて、詳細を開くと能力の全面（モデル、SOUL、スキル、
ツール群、MCP サーバー）が出ます。区分にまとめることもできますし、複数の
ボットが話し合うグループ対話を開くこともできます。グループ対話は、Discord
のような独立した行として名簿に現れ、重なったメンバーのアバター、人数、直近の
発言のさわり、そして「あなたが必要」のバッジが付き、ボットの行と同じ「固定と
新しさ」の並び順で混ざります。グループの行をクリックすると、その部屋が
**主対話ウィンドウ**を占めるタブとして開きます（古いデスクトップ版では、
ボットの脇のパネルの中で開きます）。

ボットどうしもやり取りします。どの対話でも `@researcher have a look at this`
と入力すれば、いま動いているボットがメッセージを渡して結果を報告しますし、
ボットは互いの Bot Chat へ直接届きます（`hermes -p <bot> chat`）。バックエンドは
各ボットの正式な **Bot Chat** セッションに、メッセージのやり取りの作法を自動で
教えます（設定 `agent.bot_mode_protocol`、既定は有効）。仲間のボットが CLI から
画面無しで開いた場合も同様です。おかげでボットどうしの返信や引き継ぎは、
SOUL.md に手を入れなくても動きますし、ふだんのセッションには何の影響もありません。

Bot Mode のセッション（各ボットの正式な Bot Chat と、グループ対話の
メンバーのセッション）は、全体の Sessions のサイドバーからは常に隠されます。
自分の会話と混ざるのではなく、Bots のペイン（名簿の行、部屋の表示、各ボットの
セッション一覧）の中にあります。

使わないボットはしまっておけます。ボットの行を右クリックして **Hide
Bot** です。隠したボットは名簿から消えますが、動き続けます。@ の呼び出しは
届きますし、グループ対話の所属もそのままです。1 体でも隠れていると Bots の
見出しに目のアイコンが出て、押すと隠れたボットが薄い表示でその場に現れます
（右クリック → **Unhide Bot** で戻せます）。隠れたボットに未読の動きがあると、
目のアイコンに点が付きます。隠れているかどうかはボットのプロファイルに
保存されるので、端末をまたいでも付いてきます。

要りませんか。**Capabilities → Plugins → Bots** で **Desktop** のスイッチを切ってください。名簿、
ルーティンのペイン、入力欄のミドルウェアがその場で登録解除され、再起動は要りません。

詳しい案内 — エージェントの作成（複数の端末にまたがる **Create on**
の選択欄を含みます）、接続をまたいだ名簿、ボットどうしの呼びかけ、グループ
対話で誰が返すかの決まり方: [Bot Mode: エージェントの名簿](/hermes/docs/user-guide/bot-mode/)。

### キーボードと移動 {#keyboard-navigation}

- **コマンドパレット** — **Cmd+K** か **Cmd+P**（Windows と Linux では Ctrl+K / Ctrl+P）を押すと、キーボードだけで操作へ飛び、アプリの中を移動できます。任意のページや設定の項目を開く、題名や id でセッションへ飛ぶ、モデルやテーマや配色モードを切り替える、ターミナルを起こす、ゲートウェイを再起動する、Hermes を更新する、などができます。
- **付け替えられるショートカット** — **Settings → Keyboard Shortcuts**（または **Cmd/Ctrl+/**）でショートカットのパネルが開き、ほぼすべての割り当てを付け替えられます。プロファイルの切り替え、セッションの移動、表示の切り替え、そしてデスクトップのプラグインが足したショートカットも対象です。重複した割り当ては衝突として印が付きます。覚えておくとよい既定値をいくつか挙げます。**Cmd/Ctrl+N** は新しいセッション、**Cmd/Ctrl+.** は Command Center、**Cmd/Ctrl+,** は設定、**Cmd/Ctrl+Shift+F** はセッション検索、**Cmd/Ctrl+1–9** はプロファイルの切り替え、**Shift+X** は明暗の切り替えです。
- **拡大縮小のショートカット** — 画面を半段階ずつ拡大縮小できるので、文字の大きさを細かく調整できます。
- **表示言語の切り替え** — アプリの表示言語をアプリ内で変えられます。英語、簡体字中国語（zh-Hans）、繁体字中国語（zh-Hant）、日本語、アラビア語（右書き）、ロシア語に対応します。

### セッションとプロファイル {#sessions-profiles}

- **セッション一覧の刷新** — 保管の機能と、全体的な整理の仕組みを備えた新しいセッション一覧です。数が増えても扱える状態を保ちます。
- **id でセッションを検索** — 特定のセッションを id から直接見つけられます。
- **複数プロファイルの同時セッション** — 複数の[プロファイル](/hermes/docs/user-guide/profiles/)にまたがるセッションを同時に動かせますし、プロファイルをまたぐ `@session` のリンクで、別プロファイルのセッションを参照できます。
- **プロファイルの書き出しと取り込み** — 環境ひとそろいを 1 つのファイルとして渡せます。**⌘K → Export profile…**（またはレールのプロファイルの四角を右クリック）で、スキル、記憶、人格、cron、プラグイン、設定を含む `.tar.gz` が書き出されます。API キーは取り除かれます。デスクトップから書き出すと、外観と表示（外皮、明暗モード、独自テーマ、そのプロファイルのレールの色、ウィンドウの配置）も一緒に束ねられるので、取り込んだプロファイルは送り手が見ていたとおりの姿で届きます。取り込みは **⌘K → Import profile…** か、レールの **+** の隣のボタンから行います。重ね書きが適用され、新しいプロファイルの中へ入ります。同じ書庫は、対話の中の `/export` と `/import`、シェルからの `hermes profile export` と `import` でも使えます。[プロファイルのファイルを書き出す・取り込む](/hermes/docs/user-guide/profile-distributions/#export-and-import-a-profile-file)を参照してください。

## 更新 {#updating}

アプリは裏で更新を確認し、用意ができるとワンクリックの更新を提案します。

手元での更新のあいだ、詳しいビルドの出力は、動いているプロファイルの
`logs/update.log` へ流れます。切り離された `--gateway` の更新も同様です。端末には
出ませんが、ビルドが終わる前でも問題の切り分けに使えます。Windows の
引き継ぎ処理は、このログの新しい出力を進行の証拠として数えます。出力を出さない
子プロセスは、それでも無反応の見張りの対象です。プロセスが生きていることだけでは
その見張りは戻りませんし、更新を取り消してもビルドが終わるのを待つことはありません。

デスクトップアプリと、それが話す相手の Hermes バックエンドは、別々の時計で更新されます。アプリの一式は手元の端末で、バックエンドはそれが動いている場所で更新されます。更新の対象が 2 つ以上あるとき（リモートのゲートウェイや、登録された複数のゲートウェイ）、更新の入り口（About パネルの **Update now**、⌘K の **Update Hermes** の行、更新準備完了の通知）は**すべて**を更新します。まずつながっているバックエンド、次に対象となる他の登録済みゲートウェイすべて（Hermes Cloud の項目は基盤側で管理されるので飛ばされます）、そして最後にデスクトップアプリ自身です。クライアントの更新を当てるとアプリが再起動するためです。端末 1 台の環境では、ボタン 1 つの体験のままです。

バックエンドを更新したあとは、アプリが自分自身のバージョンも確認し直し、画面側が遅れていればワンクリックの **Update desktop app** を添えて警告します。リモートのバックエンドを更新した結果、古いデスクトップ版のまま黙って取り残されることが無いようにするためです。

[手動での更新手順](https://hermes-agent.nousresearch.com/docs/getting-started/updating)も、画面付きの環境で使えます。

## 削除する {#uninstalling}

**Settings → About → Danger zone** を開いて、どこまで消すかを選びます。

- **Uninstall Chat GUI only** — デスクトップアプリとそのデータを消します。Hermes のエージェント、設定、対話は残ります。（`hermes uninstall --gui` と同じです。）
- **Uninstall GUI + agent, keep my data** — アプリとエージェントを消しますが、設定、対話、秘密情報は将来の再導入のために残します。（`hermes uninstall` と同じです。）
- **Uninstall everything** — アプリ、エージェント、そしてすべての利用者データを消します。（`hermes uninstall --full` と同じです。）

作業を終えるためにアプリは閉じます（後始末はアプリの終了後に走るので、動いているアプリ一式と自分の venv を消せます）。手元にエージェントが導入されていない場合（たとえばリモートのバックエンドにつないだ画面だけの「lite」クライアント）、エージェントを消す選択肢は自動的に隠れます。

同じことは端末からもできます。画面だけなら `hermes uninstall --gui`、エージェントも消すなら `hermes uninstall` か `hermes uninstall --full` です。

:::note
**ソースのチェックアウト**（`hermes desktop` の開発ビルド）から `hermes uninstall --gui` を実行すると、作業スペースの `node_modules` と `apps/desktop/{dist,release}` のビルド成果物も消えます。これらは画面側のビルド生成物だからです。`hermes desktop`（あるいは `npm install` と再ビルド）で復旧できますが、デスクトップアプリ自体をいじっている最中なら、そのあと依存関係を入れ直すことになります。
:::

## CLI 早見表: `hermes desktop` {#cli-reference-hermes-desktop}

CLI から起動するには、`hermes desktop` を実行するだけです。既定では、作業スペースの Node の依存関係を導入し、いまの OS 向けに展開済みの Electron アプリをビルドしてから、そのビルド成果物を起動します。

Linux では、起動のたびに `$XDG_DATA_HOME/applications/hermes.desktop`（既定では `~/.local/share/applications/hermes.desktop`）が更新され、Hermes がアプリケーションメニューに現れます。手で編集した項目を保ちたい場合は、更新を無効にしてください。

```bash
hermes config set desktop.manage_launcher_entry false
```

項目が無い場合は、それでも作られます。このフラグは `hermes desktop` がすでにある項目を書き換えるのを止めるだけです。

| フラグ                 | 説明                                                                               |
| -------------------- | ----------------------------------------------------------------------------------------- |
| `--skip-build`       | npm の導入とパッケージ化を飛ばし、`apps/desktop/release` にある展開済みのアプリを起動します |
| `--force-build`      | 内容の印が一致していても、完全な再ビルドを強制します                                    |
| `--build-only`       | デスクトップアプリをビルドしますが、起動はしません（`hermes update` が使います）                      |
| `--source`           | パッケージ化したアプリではなく、`apps/desktop/dist` に対して `electron .` で起動します           |
| `--cwd PATH`         | デスクトップの対話セッションの最初のプロジェクトディレクトリ（`HERMES_DESKTOP_CWD` を設定します）           |
| `--hermes-root PATH` | アプリが使う Hermes のソースの根を上書きします（`HERMES_DESKTOP_HERMES_ROOT` を設定します）          |
| `--ignore-existing`  | バックエンドの解決時に、`PATH` 上にすでにある `hermes` の CLI を無視させます      |
| `--fake-boot`        | 起動時の画面を確かめるために、決まった長さの起動待ちを入れます                            |

## しくみ {#how-it-works}

パッケージ化されたアプリには、Electron の外殻と、React で書かれたネイティブな対話画面が入っています。初回の起動時に、Hermes Agent のランタイムを `HERMES_HOME`（`~/.hermes`、Windows では `%LOCALAPPDATA%\hermes`）へ導入できます。これは **CLI で導入した場合とまったく同じ構成**で、だからこそ両者を行き来できます。バックエンドの解決は、まず `HERMES_DESKTOP_HERMES_ROOT`、次に導入が完了した管理下のもの、次に `PATH` 上で見つかった `hermes`（`--ignore-existing` や `HERMES_DESKTOP_IGNORE_EXISTING=1` が設定されていない場合）、最後に Nix のようなパッケージ作成者向けの明示的な `HERMES_DESKTOP_HERMES` コマンドの上書き、の順に見ます。React の描画側は、アプリが起こす画面無しのバックエンドと話します。これは `tui_gateway` の JSON-RPC / WebSocket API を提供する `hermes serve` のプロセスで、`hermes --tui` を埋め込むのではなくエージェントのランタイムを使い回します。デスクトップアプリは**自己完結**しています。自前の `hermes serve` バックエンドを動かし、[Web ダッシュボード](/hermes/docs/user-guide/features/web-dashboard/)を開くことも必要とすることもありません。（`serve` コマンドより古いランタイムの場合は、画面無しの `dashboard --no-open` へ自動で下がるので、アプリの更新がバックエンドを追い越してしまうことはありません。）導入、バックエンドの解決、自己更新の処理は Electron の主プロセスにあります。

## リモートのバックエンドにつなぐ {#connecting-to-a-remote-backend}

既定では、アプリは自分の**手元の**バックエンドを起こして管理します。代わりに、別の端末で動いている Hermes のバックエンド（VPS、自宅のサーバー、Tailscale の向こうの Mini など）を指すこともできます。

接続に関わることは、すべて 1 つの設定ページにあります。**Settings → Gateways** です。（古い版では **Gateway** と **Connections** の別ページに分かれていました。今は統合され、古い `?tab=connections` のディープリンクは統合後のページへ転送されます。）

**Settings → Gateways → Connection mode** には、手元のゲートウェイ以外の選択肢が並びます。

- **Remote gateway** — 自分で動かしている `hermes serve` のバックエンドの URL を入力してサインインします。この節で説明するのはこのやり方です。
- **Hermes Cloud** — Hermes Cloud に一度サインインして、自分のアカウントにあるエージェントから選びます。URL を貼る必要はありません。アプリがエージェントを見つけ（アカウントが複数の組織にまたがる場合は組織の選択欄が出ます）、1 つにつなぐとセッションが自動で切り替わります。つながっているあいだ、ステータスバーにクラウドの接続が表示されます。

ゲートウェイの接続は**端末単位**です。Gateways のページは、このデスクトップがどのゲートウェイのバックエンドにつなげるかを管理し、プロファイルはつないだゲートウェイ*から*見つかります。セッションは一度に 1 つのゲートウェイを選び、隣のプロファイルのレールで、そのゲートウェイ上に見つかったプロファイルを選びます。

### 複数接続の登録簿 {#the-multi-connection-registry}

同じ **Settings → Gateways** のページの下のほうにある **Registered gateways** は、アプリが知っているすべての Hermes のゲートウェイに名前を付けて管理します。手元のランタイム、いくつでも登録できるリモートのゲートウェイ（LAN、Tailscale、インターネット）、Hermes Cloud のインスタンス、SSH のホストが、1 か所にまとめて保存されます。サイドバーのプロファイルのレールの右端にあるプラグのボタン（**Connect another Hermes gateway…**）か、**⌘K → Gateways** から飛べます。全体をまとめたエージェントの名簿、`@name-device` の呼び名、全ゲートウェイ一括の更新、プラグイン SDK の面などを含む詳しい案内は、[デスクトップを多数の Hermes につなぐ](/hermes/docs/user-guide/multi-connection-desktop/)にあります。

- **どの接続にも固有の名前が要ります**（「Homelab」「Work laptop」といった端末名です）。同じプロファイル名が複数の登録済みゲートウェイに存在するときは、各所で `@profile-device` の形で区別されます（例: `@research-homelab`）。
- **ゲートウェイは Sessions のサイドバーから切り替えます。** ゲートウェイが 2 つ以上登録されると名前付きの選択欄が現れ、登録簿がどれだけ大きくてもゲートウェイをプロファイルのように見せずに扱えます。隣のプロファイルのレールには、そのゲートウェイのエージェントだけが出て、そこで最後に使ったプロファイルを覚えます。プロファイルが多い場合は、そちらはそちらで独立にまとめられます。
- **プロファイルの帯を隠せます。** プロファイルを作業場所ではなくボットとして使っている場合、サイドバーの下にある色付きのプロファイルの四角が並んだ帯は、セッションの一覧と中身が重なります。セッションの表示メニュー（**Profile rail**）、シェルの右クリックメニュー、または **⌘K → Toggle profile rail** から非表示にできます。隠している間は、ステータスバーのゲートウェイの選択の隣に **Profiles** のドロップダウンが現れ、同じ選択肢（このゲートウェイのプロファイル、ほかのゲートウェイのエージェント、**New profile**、**Import profile…**、**Manage profiles…**）が並ぶので、プロファイルを切り替える入口がなくなることはありません。
- **再起動後に何を開くかを選べます。** **Open on launch** は、これまでと同じ **Primary gateway** を既定にするか、**Last used** のゲートウェイに正常につながったあとで再開するかを選べます。この設定はアプリの一式の外に保存されるので、デスクトップの更新をまたいで残ります。
- **接続の追加・編集・削除・検査**をパネルから行えます。**Add** の流れでは 4 種類すべて（**Local**、**Hermes Cloud**、**Remote gateway**、**SSH**）を選べます（アプリが管理する手元の項目があるあいだ Local のボタンは押せません。クラウドの追加については、上のサインインと検出の流れを案内するヒントが出ます）。手元の項目はアプリが管理しており、削除できません。**Test** は、その接続自身の HTTP と WebSocket の経路を直接確かめます。
- **重複は保存時に拒否されます。** **local** の項目は常に 1 つだけです。リモートとクラウドの項目は、正規化した URL（前後の空白を除き、末尾のスラッシュを外し、小文字にしたもの。両方の種類をまたいで比較します）で重複を排除します。SSH の項目は、正規化した `user@host:port` とリモートのプロファイルで比較します。
- 登録簿を持つ版を初めて動かしたとき、既存の設定は**自動で取り込まれます**。いまの全体の接続と、以前のプロファイルごとの上書きが、名前付きの項目になります。以前の設定ファイルには手を触れないので、古い版もそのまま動きます。
- クラウドの項目は、上の Hermes Cloud のサインインと検出の流れから来るもので、手で URL を打ち込むものではありません。
- トークンは OS のキーリングで暗号化して保存されます（キーリングの無い Linux では、平文で保存することに明示的に同意する必要があります）。

横並びの経路制御はすでに動いています。登録された各ゲートウェイは、必要になった時点で自分のバックエンドとソケットをつなぎ（接続とプロファイルの組ごとに分かれます）、プラグイン SDK は全体をまとめたエージェントの名簿を提供し（`host.agents()` と `host.ensureAgent()`）、Gateways のページの **Update all instances** は、対象となるすべてのゲートウェイへ一斉に `hermes update` を送ります。Hermes Cloud の項目は飛ばされ（基盤側が更新します）、各インスタンスは自分の結果を報告します。

:::info リモートのバックエンドとは、動いている `hermes serve` のプロセスです
「リモートのバックエンド」とは、リモートの端末で動いている **`hermes serve`** のサーバーのことです。デスクトップアプリがつなぐのはこのプロセスです。そのバックエンドが実際に起動していて届く状態でなければ、この節の内容は何も動きません。デスクトップアプリが起こしてくれるわけではありません。自分（あるいは `systemd` のサービス）がリモートのホストで `hermes serve` を動かし続け、アプリがそこへつなぎます。メッセージのチャンネル（Telegram、Discord など）も使う場合、**ゲートウェイ**は*別の*長時間動くプロセスで、自分で起動します。設定手順のあとの注記を参照してください。
:::

接続には 2 つの側面があります。バックエンド側では**認証プロバイダー**で守り、アプリ側ではバックエンドの URL を入れてサインインします。バックエンドをループバック以外のアドレスに割り当てると、自動的に認証の関門が働き、設定したプロバイダーがデスクトップアプリを通す役目を果たします。

**バックエンドがどこにあるかでプロバイダーを選んでください。**

- **OAuth（Nous Portal） — 自分の端末の外から届くものには、こちらを推奨します。** ログインは Nous のアカウントに対して検証されるので、VPS、公開ホスト、そのほかリモートのバックエンドにはこちらが適します。`hermes dashboard register`（または Portal の [`/local-dashboards`](https://portal.nousresearch.com/local-dashboards) のページ）でダッシュボードを登録して OAuth のクライアントを用意し、アプリから **Sign in with Nous Research** でサインインします。自前の ID プロバイダーを運用しているなら、自己ホストの OIDC プロバイダーも同じように使えます。
- **ユーザー名とパスワード — 手元や信頼できるネットワークでのみ使ってください。** バックエンドが同じ信頼できる LAN 上にあるか、VPN（Tailscale など）経由でしか届かない場合に、いちばん手軽な方法です。外部の ID プロバイダーを使わずに、共有の認証情報 1 組で守るだけなので、**公開インターネットに晒したダッシュボードには使わないでください**。そこでは OAuth を選んでください。

この節の残りでは、信頼できるネットワークでいちばん早く立ち上げられるという理由で、ユーザー名とパスワードの経路を示します。OAuth の経路については、[Web ダッシュボード → 既定のプロバイダー: Nous Research](/hermes/docs/user-guide/features/web-dashboard/#default-provider-nous-research)を参照してください。

### バックエンド側（リモートの端末）で {#on-the-backend-the-remote-machine}

ユーザー名とパスワードを設定し、届くアドレスに割り当ててバックエンドを起動します。認証情報は `~/.hermes/.env`（権限 0600 の秘密情報のファイル）に置きます。

```bash
# 1. Set the dashboard login credentials.
cat >> ~/.hermes/.env <<'EOF'
HERMES_DASHBOARD_BASIC_AUTH_USERNAME=admin
HERMES_DASHBOARD_BASIC_AUTH_PASSWORD=choose-a-strong-password
# Recommended: a stable signing secret so sessions survive restarts.
# Without it a random key is generated per boot and you'll be logged out
# on every restart.
HERMES_DASHBOARD_BASIC_AUTH_SECRET=$(openssl rand -base64 32)
EOF
chmod 600 ~/.hermes/.env

# 2. Run the backend bound to a reachable address. The non-loopback bind
#    engages the auth gate; the username/password provider handles login.
hermes serve --host 0.0.0.0 --port 9119
```

デスクトップアプリからつなげる状態を保ちたいあいだは、この `hermes serve` のプロセスを動かし続けてください。止まればアプリはバックエンドに届かなくなります。ログアウトや再起動を越えて生き延びるよう、`systemd`、`tmux`、あるいは好みのプロセス管理の下で動かしてください。

これとは別に、メッセージのチャンネルを使っているなら、リモートのホストで**ゲートウェイが動いていること**を確かめてください。デスクトップアプリが話す相手は `hermes serve` のバックエンドですが、Telegram や Discord、Slack のゲートウェイのセッションは別のプロセスで、自分で起動して動かし続けます。ゲートウェイの設定については[メッセージ連携](/hermes/docs/user-guide/messaging/)を参照してください。

平文のパスワードをディスクに置きたくありませんか。代わりに `HERMES_DASHBOARD_BASIC_AUTH_PASSWORD_HASH` に scrypt のハッシュを設定してください。ハッシュは `python -c "from plugins.dashboard_auth.basic import hash_password; print(hash_password('PW'))"` で計算できます。設定できる項目の全容（config.yaml のキー、すべての環境変数、流量制限）は [Web ダッシュボード → ユーザー名とパスワードのプロバイダー](/hermes/docs/user-guide/features/web-dashboard/#usernamepassword-provider-no-oauth-idp)にあります。

バックエンドを systemd のサービスとして動かしますか。その場合はユニットに `EnvironmentFile=%h/.hermes/.env` を書いて、起動時に認証情報が環境へ入るようにしてください。

:::warning
バックエンドはあなたの `.env`（API キーや秘密情報）を読み書きし、エージェントのコマンドを実行できます。上に示した**ユーザー名とパスワード**の設定は、信頼できるネットワーク向けです。パスワードで守っただけのバックエンドを、そのまま公開インターネットに晒さないでください。VPN の内側に置いてください。[Tailscale](https://tailscale.com/) が素直な選択肢です。端末の tailscale の IP に割り当て（`--host <tailscale-ip>`）、Remote URL に `http://<tailscale-ip>:9119` を使えば、自分の tailnet からしか届きません。公開インターネット越しにバックエンドへ届かせたい場合は、**OAuth（Nous Portal）**のプロバイダーを使ってください。
:::

### アプリ側で {#in-the-app}

**Settings → Gateways → Remote gateway** です。

1. **Remote URL** — `http://<backend-host>:9119`（リバースプロキシを前に置いているなら `/hermes` のようなパスの接頭辞も使えます）
2. **サインイン** — アプリはバックエンドが名乗るプロバイダーを見分けて、ボタンを合わせます。ユーザー名とパスワードのバックエンドなら **Sign in** のボタンが出て、認証情報の入力欄が開きます（手順 1 の認証情報を入れてください）。OAuth のバックエンドなら **Sign in with `<provider>`**（たとえば *Sign in with Nous Research*）が出て、そのプロバイダーのブラウザーでのサインインが走ります。どちらの場合も、最終的にバックエンドに対して認証済みのセッションを持つことになります。
3. **保存して接続し直す** — デスクトップの外殻がリモートのバックエンドへ切り替わります。セッションは自動で更新されます。`HERMES_DASHBOARD_BASIC_AUTH_SECRET` を設定していれば、再起動をまたいでもサインインしたままです。

画面を使わずに、アプリの起動前に `HERMES_DESKTOP_REMOTE_URL` 環境変数でバックエンドの URL を設定することもできます（アプリ内の設定より優先されます）。サインイン自体は、やはり Gateways の設定パネルから行います。

:::note プロファイルごとのリモートのホスト
リモートのゲートウェイのホストは[プロファイル](/hermes/docs/user-guide/profiles/)ごとに設定されるので、プロファイルごとに別のリモートのバックエンドを指すこともできますし、手元のものに留まることもできます。プロファイルを切り替えると、アプリがつなぐリモートのホストも切り替わります。
:::

### 困ったときは {#troubleshooting}

- **サインインが 401 や「Invalid credentials」で失敗する** — ユーザー名かパスワードが、バックエンドの `HERMES_DASHBOARD_BASIC_AUTH_USERNAME` や `HERMES_DASHBOARD_BASIC_AUTH_PASSWORD` と一致していません。バックエンドは、知らない利用者の場合もパスワードが違う場合も同じ一般的なエラーを返すので（どちらかを言い当てられないようにするためです）、両方を確かめてください。関門が働いているかは `curl -s http://<host>:9119/api/status | jq '.auth_required, .auth_providers'` で確認できます。`true` が返り、`"basic"` が含まれているはずです。
- **「Sign in」のボタンが出ず、セッショントークンを求められる** — バックエンドのユーザー名とパスワードのプロバイダーが動いていません。`/api/status` の `auth_providers` に `"basic"` が並びません。`~/.hermes/.env` にユーザー名とパスワード（またはパスワードのハッシュ）の両方が設定されていること、そしてダッシュボードのプロセスがそれを実際に読み込んでいることを確かめてください。
- **再起動のたびにサインアウトされる** — `HERMES_DASHBOARD_BASIC_AUTH_SECRET` に固定の値を設定してください。無いと、トークンに署名する鍵が起動のたびに作り直され、すべてのセッションが無効になります。
- **接続が拒否される、あるいは時間切れになる** — バックエンドが `127.0.0.1`（既定）に割り当てられているか、ファイアウォールや VPN がそのポートをふさいでいます。`0.0.0.0` か tailscale の IP に割り当て、信頼できるネットワークに対してポートを開けてください。

同じ設定を Web ダッシュボードの側から見たものは、[Web ダッシュボード → Hermes Desktop をリモートのバックエンドにつなぐ](/hermes/docs/user-guide/features/web-dashboard/#connecting-hermes-desktop-to-a-remote-backend)にあります。環境変数の一覧は[環境変数 → Web ダッシュボードと Hermes Desktop](/hermes/docs/reference/environment-variables/#web-dashboard--hermes-desktop)にまとまっています。

## デスクトップアプリを拡張する {#extending-the-desktop-app}

デスクトップアプリは追加で組み上げていく作りです。ペイン、ページ、サイドバーの移動項目、ステータスバーの
項目、パレットのコマンド、キー割り当て、テーマは、すべて 1 つの SDK から登録されます。自分で足すこともできます。
プラグインは ESM のファイル 1 つで、
`$HERMES_HOME/desktop-plugins/<id>/plugin.js` に置きます。アプリは数秒のうちにそれを読み込み、
保存のたびに再読み込みします。導入済みのプラグインは **Capabilities → Plugins** から動いたまま管理できます。

詳しくは [Desktop Plugin SDK](/hermes/docs/developer-guide/desktop-plugin-sdk/) を
参照してください。（これは [Web ダッシュボードのプラグインの仕組み](/hermes/docs/user-guide/features/extending-the-dashboard/)とは別のものです。）

**Capabilities → Plugins** は、Hermes を広げるものすべてをまとめて扱う画面です。
**プラグインごとに 1 行**で、スイッチの列が 2 つあります。

- プラグインが広げるのは**このアプリ**、**エージェント**、または**その両方**です。どれに当たるかは
  各行のバッジが示します。パッケージの中身から判断していて（`plugin.yaml`
  があればエージェント側、`plugin.js` があればデスクトップ側）、両方を持つプラグインも
  1 行にまとまり、2 行に分かれることはありません。
- **Desktop の列** — このアプリに読み込まれる側です。アプリ単位なので、ウィンドウがどの
  プロファイル、ゲートウェイ、離れた端末を見ていても、同じスイッチ、同じ値になります。
  デスクトップのコードを読み込む場所はただ 1 つ、`~/.hermes/desktop-plugins/` です。
  エージェントとデスクトップをひとまとめにしたパッケージのデスクトップ側は、パッケージを
  インストールしたときにアプリがそこへ写します（更新やアンインストールにも追従します）。
  そのため、プロファイルを切り替えても、ペインが読み込まれたり、外されたり、範囲が
  変わったりすることはありません。切り替えはその場で効きます。
- **Agent の列** — 選んだプロファイルのバックエンドに入っている側です
  （[エージェントのプラグイン](/hermes/docs/user-guide/features/plugins/)。user、git、project、pip、
  portable の導入が対象です）。カタログで固定した版が動いたときは **Update** のチップが出ます。
  プロファイルの選択欄がこの列の見出しにあるのは、それがこの列にしか効かないからです。
  プロファイルが 1 つだけなら、選択欄そのものがありません。
  リポジトリに同梱された内蔵のもの（基盤のアダプター、プロバイダーのプラグイン）は
  並びません。有効な状態で配られ、それぞれ専用の画面から設定するためです。
- プラグインが持っていない側には横棒が出ます。デスクトップ側はあるのに、選んだプロファイルに
  エージェント側が入って**いない**ときは **Install here** が出ます。押すと、パッケージの出どころ
  （カタログの項目か git のリモート）をもとに、そのプロファイルだけを対象にしたインストールの
  画面が入力済みの状態で開きます。[Accent Picker](https://github.com/NousResearch/hermes-desktop-accent-picker)
  のような任意の追加分は、**Install from Git** でそれぞれのリポジトリからインストールします。

その下には、プラグインを探して入れる欄があります。常に最新の [Plugin Catalog](/hermes/docs/user-guide/features/plugin-catalog/)
の選択欄では、確認済みの項目を固定されたコミットのまま、選んだプロファイルへインストールできます。
**Install from Git** は、それ以外のリポジトリを同じ「確認してからインストールする」画面で受け付けます。
任意の **Pin to commit** 欄に 40 文字のコミット SHA を 1 つ入れると、そのコミットちょうどを
インストールします（非公開のリポジトリも使えます）。固定したプラグインには、一覧で `pinned @ <sha8>`
のバッジが付きます。以前の `Settings → Plugins` へのリンクは、ここへ転送されます。

## 困ったときは {#troubleshooting}

### アプリを再起動せずにつなぎ直す {#reconnect-without-restarting-the-app}

接続表示が **Connected** のままなのに、デスクトップの対話やボットが応答しなくなった場合は、そのボットやプロファイル、あるいはゲートウェイを選び、ステータスバーのゲートウェイのメニューを開いて **Reconnect gateway** をクリックしてください。つなぎ直しは、開いている・接続中・切断済みのどの状態でも使えます。デスクトップを再起動することも、他の経路のソケットをわざと閉じることもなく、いま使っている経路をつなぎ直します。選んだソケット上で処理中の要求は中断されることがあります。これは明示的な復旧の操作であって、バックエンドやモデルの再起動ではありません。

### 失敗したターンは、どの層で失敗したかを名指しします {#failed-turns-name-the-failing-layer}

ターンが失敗すると、対話には**どの層が失敗したか**を名指しするエラーカードが
出ます。プロバイダーやモデル、独自のエンドポイント、ストリーミングの接続、
認証、請求、ゲートウェイ、手元のランタイム、ディスクといった層で、
一般的なエラー通知で済ませることはありません。カードには、その失敗に合った復旧の操作が並びます。

- **Retry** — 失敗したターンをその場でやり直します（内容ポリシーによる拒否のように、
  やり直しても必ず同じ結果になる場合は表示されません）。
- **Switch provider** — プロバイダー、エンドポイント、認証、請求の失敗のときに、
  Settings → Models へ飛びます。
- **Open logs** — `HERMES_HOME/logs` をファイル管理ソフトで開きます。リモートや
  クラウドの接続では、このボタンは **Open Desktop logs** になります。失敗したターンの
  ゲートウェイやエージェントのログはリモートの端末にあるので、手元のデスクトップ側の
  ログ（通信の証拠）を開きます。
- **Send diagnostics** — 明示的な同意の確認のあと、伏せ字処理をした診断一式を Nous の
  内部保管領域へ送ります（`hermes debug share --nous` と同じ経路です。秘密情報は常に
  伏せられ、一式は Nous のスタッフだけが見られ、14 日後に自動で消えます）。成功すると、
  問い合わせのやり取りに貼れる非公開の閲覧リンクと、GitHub Issues、Nous Portal の
  サポート、Discord への近道が得られます。リモートやクラウドの接続では、バックエンドが
  自分のエージェントとゲートウェイのログをまとめ、手元のデスクトップのログも一緒に
  添えられるので、サポートは両方の側を見られます。
- **Copy error details** — 層、コード、プロバイダーとモデル、エラーメッセージを
  まとめた短い平文の要約をコピーします。不具合の報告や Discord に貼れます。

層の判定は、エージェントの再試行の処理が使っているのと同じエラー分類器から来るので、
メッセージの文面からの推測ではなく、実際の失敗の意味を反映します。
この記述の仕組みより古いバックエンドでも、一般的な題名と、Retry / Open logs /
Copy error details の操作を備えたカードは表示されます。

起動時のログは `HERMES_HOME/logs/desktop.log` に残ります（バックエンドの出力と、直近の Python のトレースバックも含みます）。アプリが起動の失敗を報告したら、まずここを見てください。CLI から追いかけることもできます。

```bash
hermes logs gui -f
```

よく使う初期化の手順です。

```bash
# Force a clean first-launch setup (macOS/Linux)
rm "$HOME/.hermes/hermes-agent/.hermes-bootstrap-complete"

# Rebuild a broken Python venv (macOS/Linux)
rm -rf "$HOME/.hermes/hermes-agent/venv"

# Reset a stuck macOS microphone prompt
tccutil reset Microphone com.nousresearch.hermes
```

### 「The host key has CHANGED since you last connected」（SSH のリモート） {#the-host-key-has-changed-since-you-last-connected-ssh-remote}

SSH のリモートを入れ直したり、ホストキーを更新したりすると、SSH は安全側に倒れて
失敗し、デスクトップは再試行せずエラーの重ね表示で止まります（古い鍵を消すまで、
再試行が成功することはありません）。その変更が想定どおりであることを確かめてから、
古い項目を削除して重ね表示から再試行してください。

```bash
ssh-keygen -R <host>
```

項目を消したあと、**Retry** をクリックしてください（または Settings → Gateway で
接続を設定し直してください）。止まっていた状態が解除され、次の起動で新しくつなぎ直します。

### 「Build desktop app」が Electron のダウンロードで止まる {#build-desktop-app-stuck-on-electron-download}

ビルドは Electron のランタイム（約 114&nbsp;MB）を `github.com/electron/electron/releases` からダウンロードします。導入作業が **Build desktop app** の段階で止まり、その場の出力に `retrying attempt=…` が繰り返し出ているなら、そのネットワーク（ファイアウォール、プロキシ、地域）で GitHub がふさがれているか、絞られています。

導入処理はこれを自動で立て直します。ビルドに失敗すると、(1) 壊れたキャッシュ済みの Electron の zip を消して再試行し、(2) それでも失敗し `ELECTRON_MIRROR` を設定していなければ、事実上の Electron のコミュニティミラーである `npmmirror.com` を通してもう一度試します。`@electron/get` はダウンロードの SHASUM を確かめますが、チェックサム自体も同じミラーから来ます。つまり検出できるのは壊れた・欠けたダウンロードであって、乗っ取られたミラーではありません。第三者のホストを信頼したくないなら、自分で `ELECTRON_MIRROR` を指定してください（下記）。ビルドが自分の設定を上書きすることはありません。

企業内や信頼できるものなど、**自分のミラーを選ぶ**には、導入の前に `ELECTRON_MIRROR` を設定するか、手で再ビルドしてください。ビルドはそれを尊重し、上書きしません。

```bash
ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ \
  bash -c 'cd "$HOME/.hermes/hermes-agent/apps/desktop" && CSC_IDENTITY_AUTO_DISCOVERY=false npm run pack'
```

**ミラーが必要な、その他のネイティブなダウンロード（Windows の `get-windows` の事前ビルドなど）について:** npm のキーを `$HERMES_HOME/npmrc`（Windows では `%LOCALAPPDATA%\hermes\npmrc`、それ以外では `~/.hermes/npmrc`）に置いてください。たとえば `node_get_windows_binary_host_mirror=https://<mirror>/sindresorhus/get-windows/releases/download/` のように書きます。更新処理が起こす `npm ci` と `npm run`（デスクトップ、Web、TUI のビルド）は、このファイルがあれば `NPM_CONFIG_USERCONFIG` をそこへ向けるので、設定は `hermes update` を越えて残ります。リポジトリ直下の `.npmrc` は git の管理下にあって更新のたびに自動で退避されますし、デスクトップの引き継ぎは画面側の環境を受け継ぐので `~/.npmrc` は見落とされることがあります。自分で設定した `NPM_CONFIG_USERCONFIG` が上書きされることはありません。

壊れたキャッシュの zip を手で消すには、次のようにします。

```bash
rm -f "$HOME/Library/Caches/electron"/electron-*.zip   # macOS
rm -f "$HOME/.cache/electron"/electron-*.zip            # Linux
```

## ソースからビルドする {#building-from-source}

アプリ自体に手を入れたい場合は、リポジトリの根で作業スペースの依存関係を一度導入してから、`apps/desktop` で開発サーバーを動かします。

```bash
npm install          # from repo root — links apps/desktop, web, apps/shared
cd apps/desktop
npm run dev          # Vite renderer + Electron, which boots the Python backend
```

特定のチェックアウトを指したり、実際の設定から切り離して試したりするには、次のようにします。

```bash
HERMES_DESKTOP_HERMES_ROOT=/path/to/clone npm run dev
HERMES_HOME=/tmp/throwaway npm run dev
npm run dev:fake-boot   # exercise the startup overlay with deterministic delays
```

導入ファイルを作るには、次のようにします。

```bash
npm run dist:mac     # DMG + zip
npm run dist:win     # NSIS + MSI
npm run dist:linux   # AppImage + deb + rpm
npm run pack         # unpacked app under release/ (no installer)
```

macOS と Windows の署名・公証は、必要な認証情報が環境にあれば自動で走ります（macOS は `CSC_LINK` / `CSC_KEY_PASSWORD` / `APPLE_*`、Windows は `WIN_CSC_*` です）。

### macOS の許可設定と手元での再ビルド（TCC） {#macos-permissions-and-local-rebuilds-tcc}

**フォルダーの確認をすべて 1 つの設定で黙らせられます。** macOS は Hermes が
フォルダーに触れるたびに、分類ごとに確認を出します（デスクトップ、次にダウンロード、次に書類…）。
**フルディスクアクセス**を 1 つ許可すれば、そのすべてを恒久的にカバーできます。しかも
Hermes は署名の識別子が安定しているので、更新のたびに取り直す必要もありません。

1. システム設定 → **プライバシーとセキュリティ → フルディスクアクセス**（あるいは
   `open "x-apple.systempreferences:com.apple.preference.security?Privacy_AllFiles"` を実行）
2. 使っているターミナルアプリを有効にしてください。デスクトップを使うなら **Hermes.app** も。
3. 一度きちんと終了して起動し直します。

`hermes doctor` は、いまのターミナルの文脈がすでにこの許可を持っているかを報告しますし、
`hermes setup` は macOS で持っていないときにこのヒントを表示します。

macOS は許可（フルディスクアクセス、デスクトップ・ダウンロード・書類、
アクセシビリティ、オートメーション、マイク）を、アプリの*コード署名の識別子*に
結び付けて覚えます。パスではありません。手元でビルドしたアプリや自己更新したアプリは、
識別子を固定したアドホック署名で署名されるので、許可は更新をまたいで残ります。

一度だけの注意です。識別子を固定する署名の修正（PR #73681）*より前*の版に与えた許可は、
古い cdhash に固定された条件を持っています。macOS はそうした古い許可のスイッチを
オンのまま表示し続けますが、保存された許可が再ビルドしたバイナリと一致しないので、
やはり確認を出し直します。しかも今の確認には許可のボタンが無いので、確かめ直すものが
何も無いように見えます。そうなった場合は、古い許可を一度リセットして与え直してください。

```bash
tccutil reset ScreenCapture com.nousresearch.hermes   # repeat per service
```

そのあとシステム設定で新しい項目をオンにし、Hermes をきちんと終了して起動し直します。
以降、許可は安定します。

いちばん強く保証したいなら、証明書に根ざした識別子を使ってください。yabai や skhd の
利用者が頼っているのと同じ仕組みです。自己署名のコード署名証明書を一度作り、
Hermes にそれを使うよう伝えます。次の一発のコマンドが全部やってくれます
（ログインキーチェーンに証明書を作り、`codesign` からの利用を許可し、設定を書き、
パッケージ化済みのアプリに署名し直します）。

```bash
hermes desktop --setup-tcc-identity
```

手でやることもできます。

1. キーチェーンアクセス → 証明書アシスタント → **証明書を作成…**
2. 名前は `Hermes Local Signing`、種類は*自己署名ルート*、
   証明書のタイプは**コード署名**にします。
3. キーチェーンアクセスで新しい証明書をダブルクリック → **信頼** → 
   **コード署名**を*常に信頼*にします（読み込んだ自己署名の証明書は、コード署名で
   信頼するまで有効な署名の識別子になりません。設定後は
   `security find-identity -v -p codesigning` に並ぶはずです）。
4. `hermes config set desktop.macos_signing_identity "Hermes Local Signing"`

別の名前で証明書を作ったり使ったりするには、コマンドに `--identity <name>` を
付けてください（既定は `Hermes Local Signing` です）。このコマンドは何度実行しても
同じ結果になります。更新のあとに実行し直せば、設定を指し直して再ビルドしたアプリに
署名し直します。

次の更新では、再ビルドされたアプリがその証明書で署名し直され、TCC の許可はすべて
残ります。Apple の開発者アカウントは要りません。公証済みのリリース版は見分けられ、
署名し直されることはありません。

一度だけの注意です。署名の識別子を変えると（この修正のあとの最初の更新も含みます）
アプリの識別子が一度変わるので、macOS は最後にもう一度だけ確認を出します。
以降、許可は安定します。許可が引っかかったままになったら、
`tccutil reset All com.nousresearch.hermes` でリセットして与え直してください。
