**計測側のゲート（09-01 追加・Sol / Grok レビュー済み・発火実測済み）**

| 部品 | 役割 |
|---|---|
| `/healthz`（server.py） | 応答しているプロセス本人が `process_code` / `startup_id` / `assets` を名乗る。**`data.json` から読むと、ポートを掴んだ旧プロセスが新プロセスの書いたファイルを配信した瞬間に旧コードが新コードに見える** |
| `Get-CodeState`（ps1） | 三値。`current` = 何もしない / `stale` = 入れ替えて指紋一致を確かめてから成功 / `unverified` = **殺さないが exit 1**。可用性は fail-open、正しさの主張は fail-closed |
| `Sync-Code` | `Clear-Port` が失敗したら新しいプロセスを起動しない（旧リスナーが生きていると健全性検査が通り、「反映済み」の誤報になる） |
| Watch ループ | 毎周期コードを見る。2周期連続で不一致のときだけ入れ替える（書き込み途中の二重再起動を避ける） |
| 画面の asset 自己申告 | `index.html` を直すと、開いているタブの下部に再読み込みの案内が出る（サーバー再起動ではタブは更新されない） |

**PC 再起動後の初回 `-Mode Ensure` は Windows Hello の承認が要る**（09-02 実測）。承認しないまま走らせると
stale 検知 → 旧プロセス停止 → `op run` が承認待ちで起動失敗 → 30回・約70分で諦め、の順で**ダッシュボードが止まる**
（正しさ fail-closed の設計どおりだが、止まっている間は日次の索引巡回も走らない）。再起動直後は先に `op` を1回承認してから Ensure。

**取得失敗の扱い（全収集で共通）**: 読めなかったページは分子からも**分母からも**外し、失敗件数を別に出す。
「読めなかった」は「無い」の証拠ではない。Bing の補助 API も同様に `aux_failed` で別建て。
